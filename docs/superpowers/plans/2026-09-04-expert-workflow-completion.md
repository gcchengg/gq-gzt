# 专家人才库流程补全实施计划

**目标：**补齐用户确认的邀请、资料填报、工作台审批、调用申请、人工匹配及验收入口。

**架构：**沿用 PC React 与移动端 v4 单文件原型，分别以本地模拟数据记录流程。不同源之间不承诺同步，不发送真实短信，不连接真实审批。

## 约束

- 不操作 Git；不调用验证相关 skill；仅进行普通轻量编译检查。
- 需求方统一从 PC 发起调用；小程序只服务受邀专家。
- 只有专家同意并提交完整资料，管理员才可从工作台发起分管领导审批。
- 保留现有统一侧栏、原有业务及 v3 原型。

## 实施步骤

- [x] 入库邀请：补全选人弹窗、未入库候选数据、短信预览、邀请记录、重复邀请限制。
- [x] 移动端入口：个人中心及专家区展示入库邀请和通知；同意后开放分步资料；拒绝记录原因。
- [x] 入库审批：核对与领导审批分离；发起审批校验意向及资料；保存演示流程与处理轨迹。
- [x] 调用申请：扩展背景、问题、领域、时间、交付、预算和材料权限；支持草稿续填。
- [x] 专家匹配：任务详情候选检索、硬性限制、人工选择、确认人选及邀约记录。
- [x] 交付验收：移动端草稿与版本；PC正式成果展示、通过或退回补充及状态更新。
- [x] 普通构建检查并记录实际完成范围，不把演示反馈描述为真实接口完成。
