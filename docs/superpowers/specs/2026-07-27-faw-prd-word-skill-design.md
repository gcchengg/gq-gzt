# 一汽风格 PRD Word 生成技能设计

## 1. 目标

创建并安装个人 Codex 技能 `faw-prd-word`，用于根据用户提供的需求描述、截图和参考材料生成正式 PRD Word 文档。

技能安装位置：

`~/.codex/skills/faw-prd-word`

## 2. 触发场景

当用户提出以下需求时使用本技能：

- 生成 PRD、产品需求文档或需求变更说明。
- 将零散需求和页面截图整理为 Word。
- 要求使用一汽股权品牌风格生成 `.docx`。
- 要求先确认需求内容，再生成正式 Word。

## 3. 核心约束

- 正式交付格式为 `.docx`。
- 在生成 Word 前，必须先生成 Markdown 待确认稿。
- 只有用户明确确认 Markdown 内容后，才可生成 Word。
- 不得自行补充用户未确认的业务规则。
- 不明确的业务规则标记为“待确认”。
- 用户明确表示“不需要管”的内容不得继续扩展。
- 页面截图必须使用用户提供的原始图片，不生成或伪造业务截图。

## 4. 品牌视觉规范

视觉规范参考：

`需求/一企一策/一企一策工作台优化方案20260709.pptx`

提取结果：

- 主色（一汽蓝）：`#152A8C`
- 强调色（一汽红）：`#C00000`
- 正文字体：微软雅黑
- 一级标题：一汽蓝、编号式标题、下方蓝色分隔线
- 二级标题：一汽蓝、编号式标题
- 风险、异常、驳回等强调内容：一汽红
- 图标：采用参考 PPT 中的一汽蓝单色图标风格
- 页面整体：白色背景、清晰层级、正式商务风格

## 5. 默认 PRD 结构

1. 封面
   - 文档名称
   - 副标题
   - 文档状态
   - 编制日期
   - 适用模块
2. 需求背景
3. 需求变更
   - 编号与需求名称
   - 用户已确认的具体要求
   - 页面参考截图
4. 本次变更范围
5. 待确认事项
   - 仅在确有未确认内容时显示

根据需求内容可删减无内容的章节，不创建空章节。

## 7. 工作流程

1. 读取用户需求和现有材料。
2. 查看用户提供的每张截图。
3. 整理 Markdown 待确认稿。
4. 等待用户明确确认或修改。
5. 将确认后的内容转换为 Word。
6. 应用一汽蓝、一汽红、微软雅黑、编号标题和蓝色分隔线。
7. 插入原始截图，并保持清晰度和合理尺寸。
8. 渲染 Word 为页面图片。
9. 检查分页、字体、截图、表格、标题和内容完整性。
10. 交付 `.docx`。

## 8. 生成脚本接口

生成脚本采用确认后的 Markdown 作为输入：

```bash
python scripts/generate_prd_docx.py \
  --input confirmed-prd.md \
  --output confirmed-prd.docx
```

脚本负责：

- 解析 Markdown 标题、段落、列表、表格和本地图片。
- 应用固定品牌样式。
- 保持图片与说明尽量位于同一页。
- 设置页眉、页脚和页码。
- 输出可继续编辑的 Word 文件。

## 9. 验证要求

自动检查：

- 输出文件存在且可打开。
- 文档至少包含一个标题。
- 所有 Markdown 本地图片均已嵌入。
- 主色和强调色使用正确。
- 文档中不存在 `TODO`、未替换占位符或临时路径。

视觉检查：

- 无文字截断、图片拉伸或重叠。
- 无孤立标题或明显空白页。
- 表格可读且列宽合理。
- 标题层级、编号和颜色一致。
- 一汽红仅用于需要强调的内容。

## 10. 验收标准

- 技能可被 Codex 自动发现。
- 用户请求生成 PRD Word 时能够触发。
- 未经用户确认时不生成正式 Word。
- 示例 Markdown 可以稳定生成可编辑 `.docx`。
- 生成文件符合参考 PPT 的标题、图标和主要配色风格。
- 技能目录通过官方快速校验。
