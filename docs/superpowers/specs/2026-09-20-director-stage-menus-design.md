# 董事履职四阶段独立菜单设计

日期：2026-09-20

本文是对 `docs/superpowers/specs/2026-09-15-board-governance-workbench-design.md` 中「董事履职」入口的修订。不改变聘任、准备、管理、评价各自已经实现的业务动作，只改变信息架构：一个全周期入口拆成四个平级菜单，每菜单换主对象，每菜单有独立列表页和独立详情页。

## 1. 目标与范围

当前 `/boardGovernance/directors` 用一张董事总表承载四个阶段状态，点开后再用抽屉 Tabs 切换办理。四个阶段的办理单位并不相同，总表和全周期抽屉会互相干扰。

本次把「董事履职」拆成四个侧栏菜单，每个菜单只办一个阶段，并给每个阶段独立详情路由。工作台首页、负责人任务、角色配置、移动端董事页不改产品职责。

范围：

- `src/pages/boardGovernance` 内导航、路由和董事履职相关页面
- 旧 `/boardGovernance/directors` 及 `?stage=` 深链的重定向
- 工作台首页、资料任务、计划确认任务里指向董事履职的链接

不在范围：

- 移动端 `MobileDirectorView` 的信息架构
- 负责人任务、角色配置的功能增减
- 未挂侧栏的旧页 `EvaluationResourceView`（`/evaluation`、`/resources`）删除或改造
- `/assign` 及其他非 `boardGovernance` 模块
- 后端接口；状态仍由现有页面级 mock 维护

## 2. 已锁定的产品决策

1. 左侧导航用四个平级菜单替换「董事履职」，不再保留全周期总览页。
2. 每页主对象不同：聘任看案件，准备看手册资料与年度计划，管理看董事履职过程，评价看评价批次。
3. 阶段硬卡关。上一阶段未办结，不能进入下一阶段的董事相关详情，也不能为该董事发起下一阶段动作。
4. 手册资料是硬卡关的唯一例外：公司级目录，不跟某位董事的聘任进度绑定。
5. 四页都采用「列表页 + 独立详情页」，不再使用全周期抽屉，也不做无独立 URL 的左右分栏办理台。
6. 评价不要求履职管理整年结束。管理是持续过程；硬卡关停在「该董事已经进入履职管理」。

## 3. 导航与路由

侧栏顺序：

1. 工作台首页 `home`
2. 董事聘任 `appointment`
3. 履职准备 `preparation`
4. 履职管理 `management`
5. 履职评价 `duty-evaluation`
6. 负责人任务 `duty-tasks`
7. 角色配置 `roles`

履职评价使用 `duty-evaluation`，避免占用现有未挂菜单的 `evaluation` 路由。

| 菜单 | 列表 | 详情 |
|---|---|---|
| 董事聘任 | `/boardGovernance/appointment` | `/boardGovernance/appointment/:caseId` |
| 履职准备 | `/boardGovernance/preparation` | 资料 `/boardGovernance/preparation/materials/:materialId`；董事准备 `/boardGovernance/preparation/directors/:directorId`；单份计划 `/boardGovernance/preparation/plans/:planId` |
| 履职管理 | `/boardGovernance/management` | `/boardGovernance/management/:directorId` |
| 履职评价 | `/boardGovernance/duty-evaluation` | `/boardGovernance/duty-evaluation/:evaluationId` |

旧地址一律重定向，不再渲染四阶段总表：

- `/boardGovernance/directors` → `/boardGovernance/appointment`
- `/boardGovernance/directors?stage=appointment` → `/boardGovernance/appointment`
- `/boardGovernance/directors?stage=preparation` → `/boardGovernance/preparation`
- `/boardGovernance/directors?stage=management` → `/boardGovernance/management`
- `/boardGovernance/directors?stage=evaluation` → `/boardGovernance/duty-evaluation`

管理详情上的报告、建议不另开路由，作为该董事详情页内的面板。需要单独 URL 时以后再拆，本次不做。

## 4. 阶段状态机

每位董事只有一个当前阶段，取值只能是 `appointment`、`preparation`、`management`，由办结动作推进，不允许在界面上直接改阶段。评价批次不是当前阶段：董事被纳入评价后，当前阶段仍是履职管理，人仍留在管理列表。

| 当前阶段 | 进入条件 | 本阶段可做的事 | 离开条件 |
|---|---|---|---|
| 董事聘任 | 下发推荐函，产生聘任案件 | 办理推荐函、简历、权限、选举、工商 | 案件全部步骤完成，`appointmentStatus = 已完成` |
| 履职准备 | 聘任已完成 | 为该董事维护年度计划、确认计划、推送手册、生成履职任务 | 对该董事执行「生成履职任务」 |
| 履职管理 | 已生成履职任务 | 跟踪任务、写实、建议、生成/提交/接收报告；同时可作为评价批次的可选对象 | 不自动离开。本次不引入「退出管理」动作 |

反向不自动退阶段。聘任已完成后若需补办，只打开已办结案件只读查看，或新开案件；不把该董事从准备或管理列表中移除。现有 mock 里 `lifecycleStage = "evaluation"` 在实现时改为 `management`，评价状态只用 `evaluationStatus` 和评价批次对象表达。

手册资料的新增、编辑、发起更新、查看历史不改变任何董事的阶段。

## 5. 页面设计

### 5.1 董事聘任

列表主对象是聘任案件，不是董事花名册。

默认筛选「办理中」，可切换「已完成」。列：案件号、董事、任职企业、职务、推荐函文号、当前步骤、办理人、时限、状态。主按钮「下发董事推荐函」：创建案件后进入该案件详情，不留在列表。

详情复用现有 `AppointmentFlow` 工作台，改为整页路由。步骤仍按办理角色推进。全部完成后案件进入「已完成」列表，该董事出现在履职准备下块，并允许打开 `/preparation/directors/:directorId`。

### 5.2 履职准备

列表页分上下两块，进入时不要求先选董事。

上块是公司级手册资料表：类别、名称、责任部门、责任人、频次、状态。操作：新增、编辑、发起更新、预览并推送。点击资料进入资料详情。此块不对董事做阶段过滤。

下块只列出聘任已完成的董事及其年度计划摘要：董事、任职企业、计划条数、确认进度、任务是否已生成。未完成聘任的董事不出现。点击董事进入董事准备详情；点击某条计划进入计划详情。

资料详情展示历史版本、附件和办理记录，对应现有资料历史抽屉的内容，改为独立页。

董事准备详情只做本阶段工作：预览推送手册、发起/编辑年度计划、提交确认、生成履职任务。生成任务后该董事进入履职管理列表。计划尚未全部确认时，「生成履职任务」禁用，并说明原因。

计划详情用于查看和确认单份计划，供「计划确认任务」深链。确认完成不改变董事阶段；只有生成任务才放行到管理。

现有 `/boardGovernance/plan-confirm-task` 重定向到 `/boardGovernance/preparation/plans/:planId`。现有 `/boardGovernance/material-task` 仍是部门提交任务页，归负责人任务使用；返回链接改为准备列表，不再回到 `/directors`。

### 5.3 履职管理

列表只包含已生成履职任务的董事。列：董事、任职企业、履职天数、计划完成率、进行中任务、待办建议、最新报告状态、风险。未生成任务的董事不出现；准备页提示先生成任务。

详情是该董事的履职过程页。页内页签只保留：履职概览、履职计划、履职记录、意见建议、成果报告。删除现有「履职手册」「评价结果」「任职记录」页签。若需查看上游结果，用链接跳到对应阶段的只读详情（手册回准备资料或董事准备页，任职回聘任案件）。

报告生成、提交、接收和建议办理都在管理详情完成。管理详情不发起评价、不改手册目录、不办理聘任步骤。

### 5.4 履职评价

列表主对象是评价批次。列：批次名称、类型（月度/季度/年度）、周期、覆盖董事数、评价进度、状态。主按钮「发起履职评价」。

发起时可选对象仅限已进入履职管理的董事。没有可勾选董事时，发起按钮禁用并说明原因。

详情复用现有 `DutyEvaluationWorkspace`，改为整页。在详情中确认评价人与范围，带入已接收报告和已完成履职事实，分角色打分，做结果反馈。对象行可展开查看带入依据，但不能在评价详情里改计划、补任务或改报告。事实不足时，提示回到该董事的管理详情补齐。

发起评价时把当时的已完成任务、已办建议、已接收报告做成批次快照。之后管理侧再变更，不回写已发起批次。

## 6. 数据交割

页面级状态继续放在 `boardGovernance` 根页面，四个菜单共享同一份数据，不按菜单各拷一份。

| 对象 | 写入方 | 读取方 |
|---|---|---|
| 聘任案件 | 聘任列表创建、聘任详情推进步骤 | 准备列表用 `appointmentStatus` 判断下块名单；准备董事详情做进入校验 |
| 董事当前阶段 | 聘任办结、准备生成任务 | 四个列表的过滤和详情守卫 |
| 手册资料 | 准备列表/资料详情；部门在资料任务页提交 | 董事准备详情做推送预览；管理不写 |
| 年度计划 | 董事准备详情创建、提交 | 计划详情确认；生成任务后管理详情按执行口径只读计划并写任务结果 |
| 履职任务与建议 | 负责人任务办理；管理详情查看进度、补写实 | 评价详情只带入已完成项 |
| 履职报告 | 管理详情生成、提交、接收 | 评价详情只带入状态为「已接收」的报告 |
| 评价批次 | 评价列表发起、评价详情配人打分 | 管理详情不再内嵌评价结果 |

`generatedDirectorNames` 所表达的「已生成任务」是进入履职管理的唯一条件。列表过滤和详情守卫都认这一条件，不另发明第二套标记。

## 7. 跨菜单跳转

工作台首页「进入董事履职」改为进入聘任列表。首页若展示准备类待办，跳到准备列表或对应资料/计划详情。

负责人任务：

- 资料类任务办理后返回准备列表；需要看资料档案时打开资料详情
- 计划确认打开计划详情
- 履职任务和建议打开对应董事的管理详情

四个阶段详情之间只提供只读跳转，不在目标页恢复全周期 Tabs。从管理跳到准备或聘任时，若对象已办结，详情以只读方式展示。

## 8. 拦截与空态

直接访问详情 URL 也必须守卫，不能落到旧抽屉。

出现以下情况时，渲染本阶段拦截页，说明原因，并提供「返回本阶段列表」和「去当前该办的菜单」：

- 聘任未完成，访问 `/preparation/directors/:directorId`
- 未生成履职任务，访问 `/management/:directorId`
- 评价批次不存在，或批次中不含该董事的错误入口
- `:caseId`、`:materialId`、`:planId`、`:directorId`、`:evaluationId` 找不到

列表空态按筛选区分：办理中为空表示暂无待办；已完成为空表示还没有办结记录。不要把「被硬卡关过滤掉的董事」显示成一行禁用记录。

主按钮在条件不满足时禁用并写原因，不弹出后再失败：

- 计划未全部确认，不能生成履职任务
- 没有已进入管理的董事，不能发起评价批次
- 没有可推送的已提交资料，不能预览推送手册

负责人任务打开已删除或已办结对象时，提示后回到任务列表。

## 9. 实现边界

优先把现有工作台从 `DirectorView` 抽屉里拆到独立页面，而不是重写业务：

- `AppointmentFlow` → 聘任详情
- 准备相关区块（手册表、计划表、董事选择）→ 准备列表与董事准备详情
- 资料历史抽屉 → 资料详情
- `DutyPlanWorkspace` / 计划确认页 → 计划详情
- `DutyManagement`（删掉跨阶段页签）→ 管理详情
- `DutyReportWorkspace` → 管理详情内面板
- `DutyEvaluationWorkspace` → 评价详情

`DirectorView` 的全周期列表和 `DirectorLifecycleDrawer` 不再作为办理入口。实现完成后删除或仅留重定向，避免两套入口并存。

根页面 `validKeys` 与 `navigationItems` 同步替换 `directors`。Shell 的 `activeKey` 在准备详情、聘任详情等子路由上仍高亮对应一级菜单。

## 10. 验证

必须锁住的行为：

- 侧栏可见「董事聘任、履职准备、履职管理、履职评价」，不再出现「董事履职」
- `/boardGovernance/directors` 及带 `stage` 的旧地址会跳到对应新列表
- 聘任未完成：准备董事详情进不去；不能给该董事创建年度计划
- 未生成任务：管理详情进不去
- 评价发起时的可选董事只有已进入管理的人
- 手册资料详情不依赖某位董事的阶段即可打开
- 任务页深链落到资料详情、计划详情或管理详情，不再回到总表
- 管理详情没有履职手册、评价结果、任职记录页签
- `/assign` 行为不变；`boardGovernance` 样式仍限定在本模块

现有 `src/pages/boardGovernance/index.test.js` 中断言侧栏含「董事履职」、`directors` key、以及在合并页上找四阶段文案的用例，实现时改为断言新菜单、新路由和阶段守卫。
