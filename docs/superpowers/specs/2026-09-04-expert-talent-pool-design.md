# 专家人才库双端产品设计方案

## 本轮已确认调整（优先于下文早期方案）

- 需求方统一从 PC 发起调用，小程序仅服务受邀专家；不再开放普通用户申请专家服务入口。
- 入库顺序：PC 选人邀请 → 短信提醒及小程序入库通知 → 专家同意 → 分步填写并提交完整资料 → 管理员核对 → 工作台发起分管领导入库审批 → 审批通过后办理聘用及入库。发送邀请不触发领导审批。
- 小程序个人中心及专家工作区提供可发现的“入库邀请”入口；同意前不得提交入库资料，教育工作经历、专业能力等在同意后填写。
- PC 调用申请补全背景、核心问题、领域、时间、成果、预算、材料权限；任务详情提供人工匹配和成果验收。
- 原型短信、工作台审批为显式演示；PC 与移动端未连接统一后台，不承诺跨源数据同步。
- 客户流程中的“7+5初版名单”表示当前已掌握的两批理想候选人员，不是专家类别、固定人数或配额。系统统一按可变人数的“初始推荐名单／候选专家池”管理，不设置7类、5类字段；页面完成后手工导入实际人员名单。

## 1. 文档说明

### 1.1 建设范围

本方案基于《专家人才库建设方案20269.3V4(1).pptx》形成，覆盖两个产品端：

- 管理工作台：面向一汽股权内部管理人员、需求部门、审批人员和财务人员。
- 微信小程序：面向集团内部、被投企业及外部机构专家。

首期围绕产业研究专家落地，并为资本运营、财务法务、企业运营专家预留统一扩展能力。

### 1.2 产品定位

以“专家服务任务”为业务主线，将专家入库、调用、履约、评价、费用和退出纳入同一套线上流程。工作台负责规则、审批和全局管理，小程序负责专家个人资料维护和任务履约。

### 1.3 建设目标

- 建立统一、可检索、可追溯的专家档案。
- 缩短从需求提出到专家确认的流转时间。
- 通过标签匹配、利益冲突过滤和人工确认提高专家选择质量。
- 沉淀咨询过程、专家观点和项目结果，支持后续复用与回溯。
- 对专家调用、评价、费用和出入库进行全过程留痕。

## 2. 设计原则

1. 工作台主控，小程序履约。管理规则和敏感信息不下放到专家端。
2. 一项需求对应一张调用工单，一张工单贯穿匹配、邀约、交付、评价和结算。
3. AI只提供审核提示、候选推荐和内容辅助，业务人员承担最终决策责任。
4. 专家按任务查看脱敏信息，项目材料按最小必要范围授权。
5. 关键动作保留操作者、时间、处理意见和版本记录。
6. 首期保证业务闭环，复杂模型和外部数据核验分阶段建设。

## 3. 用户与权限

### 3.1 内部角色

| 角色 | 主要职责 | 数据范围 |
|---|---|---|
| 专家库管理员 | 专家审核、标签维护、邀约协调、台账管理、出库处理 | 全部专家及全部任务 |
| 需求发起人 | 提交调用需求、确认候选人、上传材料、验收成果、评价专家 | 本人发起或参与的任务 |
| 部门负责人 | 审核调用申请、专家调整和验收结果 | 本部门任务 |
| 分管领导 | 审批入库、特殊调用和例外事项 | 分管范围内数据 |
| 财务人员 | 核对费用标准、处理付款、更新结算状态 | 已进入结算的任务及必要专家信息 |
| 公司领导 | 查看经营看板、重大任务及风险事项 | 授权范围内汇总和明细数据 |
| 系统管理员 | 账号、角色、数据字典、接口和日志管理 | 系统配置，不默认查看咨询内容 |

### 3.2 专家角色

专家通过微信小程序使用以下能力：

- 接收入库邀请并维护个人档案。
- 确认或拒绝服务邀约。
- 提交可服务时间和排期变更。
- 签署利害关系、保密等承诺。
- 查看授权范围内的任务材料。
- 提交咨询记录或交付成果。
- 查看本人服务记录、评价结果和费用进度。
- 发起信息变更、暂停服务或退出申请。

专家不能查看其他专家信息、完整候选名单、内部评分规则、项目内部审批意见及未授权材料。

## 4. 总体业务架构

```text
管理工作台                            微信小程序
专家库管理                            入库资料填报
需求与调用                            邀约确认与排期
匹配与审批                            承诺签署
履约与验收                            任务执行与交付
评价与回溯                            服务记录与费用查询
费用与运营
        \                            /
         统一业务服务层
         专家档案、标签中心、流程引擎
         任务中心、消息中心、文档中心
         费用规则、权限审计、AI能力
```

## 5. 管理工作台设计

### 5.1 首页

首页按用户角色展示不同内容：

- 我的待办：入库审核、调用审批、候选确认、交付验收、专家评价和费用处理。
- 运营概览：专家总数、可用专家数、领域覆盖率、本月调用数、任务完成率。
- 风险提醒：聘期到期、证书到期、信息待复核、利益冲突、低评分和超期任务。
- 紧缺领域：有实际需求但可用专家不足的专业方向。
- 最近任务：显示项目名称、当前环节、责任人和剩余时间。

看板默认展示汇总数据。用户进入明细时，系统再次校验其数据权限。

### 5.2 专家人才库

#### 专家列表

支持以下查询条件：

- 姓名、单位、职务、专家编号。
- 专家类别、主领域、细分方向、技术关键词。
- 人才来源、专业等级、可承担角色。
- 使用状态、聘期状态、资质状态。
- 历史项目数、综合评分、最近调用时间。

列表支持保存常用筛选、导出权限控制和批量发起年度复核。

#### 专家详情

采用“一人一档”，包括：

1. 基本信息：姓名、性别、出生日期、联系方式、所在单位、职务、职称。
2. 专业信息：专家类别、主领域、细分方向、关联领域、技术关键词、专业等级、可承担角色。
3. 履历信息：教育经历、工作经历、项目经历、研究成果、资质证书。
4. 服务信息：可服务时间、常用服务形式、服务地点、当前任务量。
5. 调用记录：任务、项目、角色、服务时间、交付状态和费用状态。
6. 评价画像：履约评分、回溯结果、优势标签、风险标签。
7. 库管理：专家编号、来源、推荐人、入库日期、聘期、使用状态、年度复核。
8. 合规信息：利益关联申报、失信提示、回避记录和限制调用原因。
9. 变更轨迹：字段变更前后内容、申请人、审核人和生效时间。

敏感字段按权限脱敏展示。身份证号仅展示必要位数，联系方式禁止普通看板用户批量导出。

### 5.3 入库管理

#### 入库流程

```text
分类推荐
  -> 发起邀请
  -> 专家确认合作意向
  -> 专家填写或推荐人代填资料
  -> 完整性与异常校验
  -> 管理员初审
  -> 分管领导审批
  -> 正式入库
```

#### 入库申请关键字段

| 字段组 | 关键字段 |
|---|---|
| 推荐信息 | 专家来源、推荐单位、推荐人、推荐理由、拟服务领域 |
| 基本信息 | 姓名、性别、出生日期、证件信息、联系方式、工作单位、职务、职称 |
| 专业能力 | 主领域、细分方向、关联领域、技术关键词、从业年限、可承担角色 |
| 履历资质 | 教育背景、工作经历、项目经历、证书、研究成果 |
| 服务意愿 | 可服务时间、服务形式、常驻地点、是否接受出差 |
| 合规声明 | 诚信情况、利益关联、保密承诺、个人信息授权 |
| 审批信息 | 初审意见、复核意见、审批意见、聘期和专家编号 |

#### AI辅助审核

- 检查必填字段、联系方式格式和附件完整性。
- 识别履历时间断层、任职重叠和明显矛盾。
- 将年龄、聘期、证书有效期与准入规则比对。
- 标记需要人工核实的异常，不直接作出拒绝决定。

若外部核验接口暂未接入，系统提供人工核验项和佐证附件上传入口。

### 5.4 调用管理

#### 调用申请

调用申请包含：

- 需求方、申请人和联系方式。
- 项目名称、项目级别、项目背景和核心诉求。
- 业务场景、所需领域、技术关键词和专家等级。
- 服务形式、计划时间、服务地点和交付截止时间。
- 期望交付物、材料密级和可见范围。
- 建议专家及建议理由。
- 预算科目和费用上限。

系统在提交时校验时间、预算、材料权限和需求完整性。

#### 智能匹配

系统先执行硬性过滤：

- 专家已暂停、限制调用或退出。
- 聘期或必要资质已经失效。
- 专家与项目主体存在已识别的利益冲突。
- 专家在服务周期内不可用。
- 专家当前并行任务达到上限。

通过过滤后计算候选评分：

| 维度 | 初始权重 | 计算依据 |
|---|---:|---|
| 专业标签匹配度 | 35% | 主领域、细分方向和技术关键词 |
| 同类场景及项目经验 | 20% | 历史项目类型、角色和交付成果 |
| 历史履约质量 | 15% | 交付性、响应效率和服务态度 |
| 观点回溯准确度 | 10% | 命中、部分命中、偏离和证伪 |
| 可用时间 | 10% | 排期匹配程度 |
| 调用均衡度 | 10% | 近期调用频次和累计任务量 |

评分权重由管理员配置并保留版本。首期数据不足时，观点回溯项不参与计算，其权重按比例分配到其他维度。

推荐结果至少展示：匹配分、命中标签、同类经验、历史评价、可用时间、近期调用次数和风险提示。系统按业务规则支持内部、被投企业和外部专家的组合推荐。

需求方可以调整候选专家，但必须填写原因。涉及跳过高分候选、选择存在风险提示的专家或突破费用上限时，系统自动增加审批环节。

#### 邀约与排期

管理员确认候选人后发出服务邀约。专家可以接受、拒绝或提出改期。

- 接受：进入承诺签署和排期锁定。
- 拒绝：必须选择原因，可补充说明。系统通知管理员处理下一候选人。
- 改期：专家提交可选时间，需求方确认后更新排期。
- 超时未处理：系统提醒专家，并在规则设定时间后通知管理员。

排期锁定前，专家必须完成利害关系和保密承诺。专家申报潜在利益关系时，任务进入人工复核，不自动判定可继续执行。

### 5.5 履约与交付

任务详情统一承载以下信息：

- 项目脱敏信息和咨询目标。
- 服务时间、形式、地点和联系人。
- 授权材料和材料有效期。
- 待办事项及完成状态。
- 咨询记录、专家观点和交付附件。
- 变更记录和沟通留痕。

交付物提交后进入需求方验收：

- 验收通过：进入评价和费用结算。
- 补充完善：填写修改意见和截止时间，任务退回专家。
- 终止任务：选择终止原因并按权限审批，保留已经发生的服务和费用记录。

### 5.6 评价与项目回溯

#### 履约评价

沿用原方案的评价结构：

| 评价维度 | 权重 | 评价内容 |
|---|---:|---|
| 交付性 | 50% | 交付完整性、咨询记录质量、结论可执行性 |
| 响应效率 | 30% | 响应及时性、节点完成情况、问题处理周期 |
| 服务态度 | 20% | 配合度、责任心和协作意愿 |

系统自动计算总分：90分及以上为优秀，60分至89分为良好，60分以下为一般。评价人必须填写事实依据，低分评价必须关联具体问题或附件。

#### 项目回溯

项目退出、论证终止或达到预设观察时间后，系统创建回溯任务。回溯人员将项目实际结果与专家历史观点逐项对照，结论分为命中、部分命中、偏离和证伪。

回溯结果写入专家画像，但不直接覆盖履约评价。管理员可以根据多次回溯结果调整能力标签或专业等级。

### 5.7 费用结算

系统根据专家来源、职级或职称、服务形式、时长和日期类型匹配费用标准，生成费用试算结果。首期费用标准通过后台配置，不在程序中写死。

结算流程：

```text
服务验收通过
  -> 系统生成费用明细
  -> 需求方确认
  -> 财务复核
  -> 付款处理
  -> 回填付款结果
  -> 专家端可查
```

费用异常包括超标准、服务时间与排期不一致、重复结算和必要凭证缺失。异常单据必须人工复核。

### 5.8 运营管理

- 专家类别、领域、细分方向和关键词维护。
- 专业等级、可承担角色和准入规则维护。
- 匹配权重、均衡轮换和并行任务上限配置。
- 费用标准、表单、邀请函、聘书和消息模板维护。
- 年度复核、续聘、暂停、限制调用和出库管理。
- 项目知识、咨询记录和优秀案例归档。
- 权限、数据范围、操作日志和接口日志管理。

## 6. 微信小程序设计

### 6.1 导航结构

底部设置“首页、任务、消息、我的”四个入口。

### 6.2 首页

首页优先展示需要专家立即处理的事项：

- 待确认邀约。
- 待签署承诺。
- 待补充资料。
- 待提交或补充交付物。
- 近期服务安排。
- 聘期、证书和年度复核提醒。

首页不展示专家排名、其他专家数量或内部运营数据。

### 6.3 入库办理

专家通过一次性邀请链接进入入库流程：

1. 验证手机号和本人身份。
2. 阅读合作说明及个人信息授权。
3. 填写或确认基本资料。
4. 维护专业领域、关键词和项目经历。
5. 上传证书和必要证明。
6. 填写服务意愿和可服务时间。
7. 提交审核。

专家可以暂存草稿。审核退回时，系统只开放需要修改的字段，并显示明确原因。正式入库后，专家可查看电子聘书和聘期。

### 6.4 任务中心

任务按以下状态筛选：待确认、待签署、待开始、服务中、待交付、待补充、已完成和已取消。

任务详情展示：

- 项目脱敏名称和核心诉求。
- 服务形式、时间地点、联系人。
- 交付要求和截止时间。
- 费用标准及预计金额。
- 可查看的任务材料。
- 当前环节、专家待办和历史操作。

专家接受邀约前只展示判断是否承接所必需的信息。接受并完成承诺签署后，系统按任务授权开放进一步材料。

### 6.5 邀约确认

专家可以：

- 接受邀约并确认排期。
- 拒绝邀约并选择原因。
- 申请调整时间。
- 申报利益关系或其他回避事项。

确认结果实时同步工作台。任务发生时间、地点或交付要求变化时，需要专家再次确认。

### 6.6 任务交付

专家可以在线填写咨询记录，或上传经允许的文档、图片及其他附件。咨询记录包含：

- 访谈基础信息。
- 咨询核心目的。
- 问题与专家答复。
- 事实、判断和推导依据。
- 风险提示和行动建议。

系统支持草稿、提交和退回补充。正式提交后内容只读，如需修改则生成新版本并保留旧版本。

### 6.7 我的

- 个人档案和联系方式。
- 专业领域、能力标签和可承担角色。
- 教育、工作及项目经历。
- 证书资质和有效期。
- 可服务时间和请假设置。
- 服务记录、评价和费用记录。
- 聘书、承诺和协议。
- 信息变更、暂停服务和退出申请。

专家发起重要信息变更后，原信息继续生效，审核通过后切换到新版本。

## 7. 核心状态设计

### 7.1 专家状态

| 状态 | 含义 | 允许的主要动作 |
|---|---|---|
| 邀请中 | 已发出邀请，专家尚未提交资料 | 重发邀请、撤销邀请 |
| 待提交 | 专家已确认意向，资料未提交 | 编辑、提交 |
| 审核中 | 入库申请正在审核 | 审核、退回、拒绝 |
| 待签约 | 审批通过，聘书或协议未完成 | 签署、撤回 |
| 可用 | 可以参与匹配和调用 | 调用、变更、复核、暂停 |
| 忙碌 | 可调用但当前任务量达到上限 | 查看、调整排期 |
| 暂停 | 专家临时无法承接任务 | 恢复、申请退出 |
| 限制调用 | 存在质量或合规事项 | 复核、解除限制、出库 |
| 待续聘 | 聘期即将到期 | 续聘、出库 |
| 已出库 | 不再参与匹配和调用 | 查看历史档案、重新申请 |

### 7.2 调用任务状态

| 状态 | 责任角色 | 退出条件 |
|---|---|---|
| 草稿 | 需求发起人 | 提交或删除草稿 |
| 审批中 | 审批人 | 审批通过或驳回 |
| 匹配中 | 系统、管理员 | 确定候选专家 |
| 邀约中 | 管理员、专家 | 专家接受或全部候选拒绝 |
| 待签署 | 专家 | 完成承诺或申报回避 |
| 待开始 | 需求方、专家 | 到达服务开始时间 |
| 服务中 | 专家 | 提交交付物 |
| 待验收 | 需求方 | 通过、退回补充或终止 |
| 待评价 | 需求方 | 提交履约评价 |
| 待结算 | 需求方、财务 | 完成付款或确认无需付款 |
| 已完成 | 系统 | 创建后续项目回溯任务 |
| 已取消 | 有权限的内部用户 | 保留取消原因和已发生费用 |

## 8. 消息与提醒

### 8.1 消息渠道

- 工作台站内消息。
- 微信小程序订阅消息。
- 企业微信、短信或邮件作为可配置补充渠道。

### 8.2 关键触发点

- 入库邀请、资料审核退回、资料审核通过、分管领导审批和正式入库。
- 服务邀约、即将超时、接受、拒绝和排期变更。
- 承诺待签署、任务开始、交付临期和交付退回。
- 验收完成、评价完成和费用状态变化。
- 证书到期、聘期到期和年度复核。
- 利益冲突、低评分和其他风险事项。

消息正文不得包含超出接收人权限的敏感项目内容。

## 9. 数据与接口

### 9.1 核心数据对象

- 专家档案。
- 专家领域标签。
- 专家资质与履历。
- 入库申请和聘书。
- 调用需求和候选推荐。
- 邀约、排期和承诺。
- 服务任务、咨询记录和交付物。
- 履约评价和项目回溯。
- 费用标准和结算单。
- 消息、审批和操作日志。

### 9.2 建议接口

- 组织与人员：获取内部用户、部门和岗位信息。
- 统一认证：工作台单点登录和小程序身份绑定。
- 流程审批：对接现有审批平台或使用独立流程引擎。
- 财务系统：预算校验、付款申请和付款结果回填。
- 电子签署：聘书、利害关系和保密承诺签署。
- 外部核验：企业关联、学历、职称、信用等信息核验。
- 消息平台：企业微信、微信订阅消息、短信或邮件。

接口未具备时，首期必须提供人工录入、附件上传和处理结果登记能力，保证流程可以闭环。

## 10. 安全与合规

- 采用角色权限、部门数据权限和任务授权三层控制。
- 项目材料设置密级、可见对象、查看期限和下载权限。
- 专家端材料默认禁止转发，敏感材料增加水印和访问日志。
- 身份证号、手机号、银行信息等敏感字段加密存储并按权限脱敏。
- 专家查看项目前先完成保密和利益关系承诺。
- 重要下载、导出、审批、调分、出库和费用变更记录审计日志。
- 专家退出后停止新增访问权限，历史业务记录按档案要求保留。
- AI处理敏感材料时使用公司批准的模型和数据边界，不将敏感数据发送到未授权服务。

## 11. 异常处理

| 场景 | 系统处理 |
|---|---|
| 专家长期未响应邀约 | 自动提醒并升级给管理员，可转邀下一候选人 |
| 全部候选专家拒绝 | 返回匹配环节，保留拒绝原因并扩大检索范围 |
| 专家申报利益冲突 | 暂停邀约确认，进入人工复核 |
| 服务期间专家退出 | 管理员选择更换专家、缩小范围或终止任务 |
| 交付物逾期 | 提醒专家和需求方，记录逾期时长并纳入评价依据 |
| 需求发生重大变更 | 生成任务变更单，重新确认专家、排期、交付和费用 |
| 费用超过标准 | 阻止自动提交，增加例外审批 |
| 接口不可用 | 记录失败原因，支持人工补录和后续重试 |
| 专家信息审核退回 | 保留已填内容，只开放需修改字段并通知专家 |

## 12. 数据看板与指标

首期指标采用可以从业务过程直接计算的口径：

- 专家规模：在库、可用、新增、暂停、出库专家数量。
- 领域覆盖：各专业方向可用专家数及紧缺专业数量。
- 调用效率：申请至确定专家的平均时长、邀约接受率。
- 任务履约：按时交付率、一次验收通过率、任务完成率。
- 服务质量：平均履约评分、优秀率、一般评价数量。
- 使用均衡：专家调用集中度、从未调用专家占比。
- 费用情况：预计费用、已结算费用、待结算金额和异常单据数量。
- 知识沉淀：咨询记录数量、可复用案例数量、完成回溯的观点数量。

所有指标必须明确统计周期、状态范围和去重方式，并支持下钻到权限范围内的明细。

## 13. 分期建设

### 13.1 一期：业务闭环

- 专家档案、标签和出入库管理。
- 专家搜索、规则匹配和人工确认。
- 调用申请、审批、邀约和排期。
- 利害关系及保密承诺。
- 服务执行、咨询记录、成果归档和验收。
- 履约评价、费用申请和进度查询。
- 微信小程序专家端。
- 消息通知、权限控制和操作日志。

### 13.2 二期：智能增强

- AI履历完整性和异常识别。
- 企业关联、学历、职称和信用信息核验。
- 自然语言找专家和推荐理由生成。
- 咨询材料摘要、观点提取和标签建议。
- 项目结果回溯和专家画像更新。
- 知识库问答和案例复用。
- 紧缺专业预测和专家寻源建议。

## 14. 一期验收标准

### 14.1 专家入库

- 推荐人能够创建入库邀请并跟踪状态。
- 专家能够在小程序完成资料填写、暂存和提交。
- 管理员能够退回、审核和完成入库。
- 系统能够生成唯一专家编号并保存聘期。
- 所有审核动作具有完整操作记录。

### 14.2 专家调用

- 需求方能够提交完整调用申请并完成审批。
- 系统能够按标签、可用性和状态生成候选清单。
- 管理员能够记录人工调整原因并完成邀约。
- 专家能够接受、拒绝或申请改期。
- 专家申报利益关系后，系统能够暂停流程并触发复核。

### 14.3 履约与评价

- 专家能够查看授权材料并提交咨询记录或附件。
- 需求方能够验收、退回补充或终止任务。
- 验收通过后，系统能够发起履约评价。
- 评价结果能够写入专家档案并用于后续查询。
- 历史交付物和修改版本能够追溯。

### 14.4 费用与管理

- 系统能够根据配置规则生成费用试算。
- 财务能够复核并回填付款结果。
- 专家能够在小程序查看本人费用进度。
- 管理员能够完成暂停、恢复、续聘和出库操作。
- 未授权用户不能查看或导出敏感信息。

## 15. 暂不纳入一期

- 专家之间的社交、讨论组和公开排名。
- 面向专家开放完整项目库或知识库。
- AI自动批准入库、自动确定专家或自动作出项目决策。
- 独立建设复杂培训考试系统。
- 与专家任务无关的人才招聘和员工绩效管理。

## 16. 设计结论

本方案以管理工作台和微信小程序组成双端产品。工作台承担全流程管理、规则配置、审批和运营分析，小程序承担专家资料维护、邀约确认和任务履约。首期优先完成可运行的业务闭环，后续在真实调用、评价和回溯数据积累后逐步增强AI匹配和知识复用能力。

## 17. 现有小程序原型改造方案

### 17.1 原型基线

小程序改造以以下文件为原型基线：

`需求/专家人才库/移动端投资合作服务平台_v3_2026-08-31_19-02_单文件分享版.html`

现有原型已经具备：

- “投资布局、产业协同、股权小智、社区论坛、个人中心”五个底部导航。
- 产业协同下的“专家人才、产品技术、资金资本、信息资源”四类服务入口。
- 专家人才下的“技术支持、管理咨询、财法咨询、国际化咨询”四类服务介绍。
- 统一的蓝色视觉规范、手机画布、列表卡片、筛选标签和二级页面框架。

现有原型尚未具备：

- 专家身份绑定和角色识别。
- 专家入库资料填报及审核反馈。
- 服务邀约、排期确认和利益关系申报。
- 专家任务执行、交付、评价和费用查询。
- 可使用的个人中心。当前个人中心为空白页面。

### 17.2 改造策略

采用低侵入的“业务门户加专家工作区”方案：

1. 保留现有五个底部导航，不将整个小程序改造成单一专家应用。
2. 保留“产业协同—专家人才—四类服务”的公众服务介绍结构。
3. 在“专家人才”页面增加角色化业务入口。
4. 将现有空白的“个人中心”改造为用户与专家身份中心。
5. 新增专家工作区承载入库、任务、档案和费用，不挤占底部导航。
6. 专家工作区沿用现有蓝色视觉、卡片圆角、顶部返回和页面滚动方式。

此方案兼顾两类使用者：普通用户可以了解和申请专家服务，已入库专家可以进入工作区完成任务。

### 17.3 双身份处理

同一微信用户可能同时具备普通用户和专家身份。登录后按以下规则处理：

| 身份状态 | 专家人才页主按钮 | 个人中心显示 |
|---|---|---|
| 未绑定 | 申请专家服务 | 登录或绑定入口、普通服务记录 |
| 已受邀未提交 | 完善入库资料 | 入库进度卡、资料草稿 |
| 入库审核中 | 查看审核进度 | 入库进度卡、已提交资料 |
| 已入库可用 | 进入专家工作区 | 专家身份卡、任务和档案入口 |
| 暂停服务 | 查看专家工作区 | 暂停状态、恢复申请入口 |
| 已出库 | 查看历史服务 | 历史任务、重新申请入口 |

专家身份通过手机号与后台专家邀请记录匹配。微信身份只用于登录，不能替代必要的本人身份验证。

## 18. 小程序页面级详细设计

### 18.1 专家人才服务页改造

#### 保留内容

- 页面标题“专家人才”。
- 蓝色主题介绍卡。
- 技术支持、管理咨询、财法咨询、国际化咨询四类服务。
- 顶部返回和横向分类标签。

#### 新增内容

在蓝色主题卡下方增加业务入口区：

- 普通用户显示“申请专家服务”主按钮和“查看服务说明”次按钮。
- 已受邀专家显示“完善入库资料”主按钮，并展示当前进度。
- 已入库专家显示“进入专家工作区”主按钮和待办数量。

服务卡增加“查看详情”，详情页展示适用场景、可提供的服务、提交需求所需材料和预计处理流程。服务介绍不直接展示专家姓名及联系方式。

#### 申请专家服务

普通用户点击“申请专家服务”后填写轻量需求：

| 字段 | 必填 | 说明 |
|---|---|---|
| 需求类型 | 是 | 技术支持、管理咨询、财法咨询、国际化咨询 |
| 需求主题 | 是 | 不超过50字 |
| 需求描述 | 是 | 说明背景、问题和期望结果 |
| 所属单位 | 是 | 从用户组织信息带入，可按权限修改 |
| 联系人 | 是 | 默认当前用户 |
| 期望时间 | 是 | 不早于当前日期 |
| 服务形式 | 是 | 会议、访谈、考察或通讯 |
| 附件 | 否 | 支持后台允许的文件类型 |

提交后生成需求编号，提示“需求已提交，工作人员将进一步确认”。小程序只展示办理状态，匹配专家和审批在工作台完成。

### 18.2 专家工作区首页

页面顶部展示专家身份卡：姓名、专家编号、主领域、专业等级、服务状态和聘期。

首页信息按优先级排列：

1. 紧急待办：待确认邀约、待签署承诺、临期交付和退回补充。
2. 近期安排：未来30天服务日程。
3. 数据概览：累计服务、进行中任务、平均评价和待结算金额。
4. 快捷入口：我的任务、我的档案、可服务时间、费用记录。
5. 状态提醒：证书、聘期、年度复核和资料完整度。

首页待办卡字段：任务名称、当前事项、截止时间、剩余时长和主操作按钮。点击整卡进入任务详情。

### 18.3 入库办理

采用分步表单，避免在手机端一次展示全部字段：

#### 第一步：身份与基本信息

- 姓名、性别、出生日期。
- 证件类型和证件号码。
- 手机号、邮箱。
- 工作单位、部门、职务和职称。

手机号默认取邀请信息，不允许直接修改。确需修改时发起人工核验。

#### 第二步：教育与工作经历

- 最高学历、毕业院校和专业。
- 教育经历列表。
- 工作经历列表。
- 从业年限。

每段经历填写开始时间、结束时间、单位、岗位和说明。系统提示时间断层或重叠，允许专家说明后提交。

#### 第三步：专业能力

- 专家类别。
- 主领域和细分方向。
- 关联领域。
- 技术关键词。
- 代表项目及本人职责。
- 可承担角色。

专家可以选择后台配置的标签，也可以提交新标签建议。新标签审核前不进入匹配模型。

#### 第四步：资质与成果

- 职业资格和职称证书。
- 代表性研究成果。
- 获奖或人才计划。
- 证明附件及有效期。

#### 第五步：服务意愿与声明

- 常驻城市和可服务地区。
- 可接受的服务形式。
- 常规可服务时间。
- 是否接受出差。
- 诚信、保密、利益关系和个人信息授权声明。

#### 第六步：确认提交

展示各步骤完成情况和缺失字段。专家确认后提交，提交内容生成版本号。审核退回时，页面标记退回步骤、字段和审核意见。

### 18.4 入库进度页

进度节点包括：邀请已发送、资料填写、资料审核、分管领导审批和正式入库。

每个节点展示状态、完成时间和处理说明。审核中的内部人员姓名不对专家展示，只显示处理部门。拒绝入库时展示可公开的结果说明和咨询渠道。

### 18.5 任务中心

#### 列表设计

顶部设置“待处理、进行中、已完成”三个主筛选，二级状态通过筛选面板选择。

任务卡展示：

- 任务名称和脱敏项目名称。
- 服务类型、专家角色和服务形式。
- 当前状态。
- 服务时间或最近截止时间。
- 主操作提示，例如“确认邀约”“签署承诺”“提交成果”。

默认将有待办的任务置顶，其次按最近服务时间排序。

#### 空状态

- 无待处理任务：显示“暂无待处理事项”。
- 无历史任务：显示“完成首次专家服务后，可在这里查看记录”。
- 网络异常：保留重试按钮，不显示为无任务。

### 18.6 邀约详情

专家确认前可以查看：

- 任务编号、服务类型和项目脱敏名称。
- 项目背景摘要和核心咨询问题。
- 服务时间、形式、地点和预计时长。
- 期望交付物。
- 费用标准说明。
- 邀约有效期。

页面底部固定“拒绝邀约”和“接受邀约”按钮。

接受时：

1. 确认本人排期。
2. 阅读保密要求。
3. 进入利害关系申报。
4. 无需回避时完成确认。

拒绝时必须选择原因：时间冲突、领域不匹配、存在利益关系、材料不足、个人原因或其他。拒绝原因只供内部调度使用，不计入履约评分。

### 18.7 利害关系与承诺

承诺页分成三部分：

- 项目主体及需核查的关联范围。
- 利害关系问题清单。
- 承诺正文和签署信息。

专家选择“存在或可能存在”时必须填写关系说明。系统将任务状态改为“待合规复核”，专家不能继续查看新增项目材料。

签署记录包括协议版本、签署人、签署时间、设备信息和文件摘要值。协议正文更新后，未完成任务是否重签由后台规则决定。

### 18.8 任务详情

任务详情采用“概览、材料、交付、记录”四个页签。

#### 概览

- 当前状态和下一步操作。
- 服务时间、地点、联系人。
- 核心诉求和交付要求。
- 任务时间线。

#### 材料

- 按项目背景、会议材料、补充材料分类。
- 显示文件名称、上传方、更新时间和有效期。
- 无下载权限时仅允许在线预览。
- 敏感材料增加专家姓名、任务编号和查看时间水印。

#### 交付

- 在线咨询记录。
- 附件上传。
- 草稿保存。
- 正式提交和退回意见。

#### 记录

- 邀约确认。
- 排期变更。
- 承诺签署。
- 材料更新提醒。
- 交付和验收结果。

内部审批意见、候选专家信息和其他专家记录不在此处展示。

### 18.9 咨询记录与成果提交

咨询记录字段：

| 字段组 | 字段 |
|---|---|
| 基础信息 | 咨询日期、方式、时长、参与人员 |
| 咨询内容 | 咨询目的、问题、专家答复 |
| 观点提炼 | 事实类信息、判断观点、推导依据 |
| 结论建议 | 风险提示、行动建议 |
| 附件 | 报告、纪要、图片及其他允许材料 |

专家可以多次保存草稿。正式提交前系统检查必填项、附件状态和敏感词提示。提交后生成只读版本；退回补充时复制上一版本生成新草稿。

### 18.10 评价展示

专家端只展示本人任务的评价结果：

- 总体等级和总分。
- 交付性、响应效率和服务态度三个维度。
- 可公开的评价说明。
- 评价时间。

项目观点回溯结果在内部确认可公开后展示。专家可以提交事实性异议，异议进入后台复核，不直接修改原评价。

### 18.11 费用记录

列表按“待确认、处理中、已支付、无需支付”筛选。费用卡展示任务、服务时间、计算依据、预计金额或确认金额和当前状态。

详情页展示：

- 服务明细。
- 适用费用规则及规则版本。
- 应付、调整和实付金额。
- 必要的税务说明。
- 付款进度和更新时间。

专家端不展示内部预算科目、内部审批人员和财务凭证中的敏感信息。

### 18.12 个人中心改造

当前空白个人中心改造为以下结构：

#### 顶部身份区

- 微信头像和姓名。
- 所属单位。
- 已绑定手机号。
- 专家身份标识和当前服务状态。

#### 专家业务区

- 专家工作区。
- 我的档案。
- 我的任务。
- 我的费用。
- 可服务时间。

未取得专家身份时，该区域显示“绑定专家邀请”或“查看入库进度”。

#### 通用服务区

- 我的服务申请。
- 消息设置。
- 用户协议与隐私说明。
- 联系工作人员。
- 退出登录。

### 18.13 可服务时间管理

专家可以设置：

- 每周常规可服务时间。
- 特定日期不可用。
- 请假起止时间和说明。
- 暂停接单状态。

已经确认的任务不因专家修改可服务时间而自动取消。发生冲突时，系统提示专家联系管理员发起排期变更。

### 18.14 小程序消息中心

消息分为待办、任务、审核、费用和系统通知。未读数量显示在个人中心入口和专家工作区首页。

消息点击后直接进入对应业务页面。失效消息仍可查看内容，但操作按钮置灰并说明失效原因。

### 20.2 需要调整的现有结构

- 当前数据全部写在前端常量中，需要将专家、任务、消息和费用改为接口数据，并统一处理加载、空数据和异常状态。

## 22. 页面验收补充标准

### 22.1 原型一致性

- 新页面在390像素画布及真实手机宽度下均无横向滚动。
- 保留现有底部导航的名称、顺序和主要视觉样式。
- 新增页面的颜色、圆角、字号和间距与现有原型一致。
- 专家工作区内部返回操作不会跳回错误的底部栏目。

### 22.2 身份与权限

- 未绑定用户不能访问专家任务、档案和费用页面。
- 专家只能访问本人任务和本人档案。
- 专家暂停或出库后，系统根据规则限制新增任务操作。
- 同一用户重新登录后，专家身份和未完成草稿可以恢复。

### 22.3 任务闭环

- 专家能够从消息或工作区进入邀约详情并完成接受、拒绝或改期。
- 接受邀约后必须完成利益关系申报才能进入任务执行。
- 专家能够保存交付草稿，弱网重试不会生成重复版本。
- 退回补充后保留上一版本和退回意见。
- 任务完成后能够查看评价和费用状态。

### 22.4 异常状态

- 每个接口页面具有加载、空数据、失败和无权限状态。
- 文件上传失败时保留已经填写的表单内容。
- 邀约或任务状态被后台变更后，前端操作前重新校验状态。
- 消息指向的任务已经失效时，页面展示结果说明而不是空白。

## 23. 聘任、续聘与年龄管理（2026-09-07确认）

### 23.1 首次聘任

分管领导审批通过后，入库申请进入“待签发聘书”，不直接正式入库。经办人配置聘书编号、3年聘期、签署截止日期和待签文件并发送，状态变为“待专家签署”；专家在小程序查看聘书并进入E签宝签署。收到签署完成回调后状态才变为“已正式入库”并生成正式专家档案。不恢复总办会环节。

### 23.2 续聘

聘期结束前90天进入续聘预警。经办人可发起续聘申请，填写续聘理由和新聘期；续聘必须由分管领导审批。审批通过后进入“待签发续聘聘书”，完成新聘书签订后续展3年聘期并恢复“聘用中”。审批退回时保留原聘期和审批意见。

### 23.3 年龄准入与解聘

普通专家年龄上限为65周岁，高层次专家为70周岁。系统依据出生日期和专家类别计算年龄上限日期，并在达到上限前90天预警。发起首次聘任、续聘和签订聘书时均需校验年龄；已超过年龄上限不得继续办理。对仍在聘期内但临近年龄上限的专家，经办人可以主动解聘，必须登记解聘原因、生效日期和说明并二次确认，历史聘书、审批和解聘轨迹永久保留。

### 23.4 状态

首次聘任：`领导审批中 → 待签发聘书 → 待专家签署 → E签宝签署完成 → 已正式入库`。

续聘：`聘用中/待续聘 → 续聘审批中 → 待签发续聘聘书 → 聘用中`。

解聘：`聘用中/待续聘 → 已解聘`。
