# 一口清页面整体 UI 精修设计

## 目标

在保留当前“一口清”页面整体布局、配色、纸质报告气质和紧凑信息密度的前提下，统一左侧企业索引、顶部筛选栏与右侧报告正文的字体体系、字号层级、行高、圆角、边框和阴影，使同层级内容具有一致的视觉规则。

本次属于体系化精修，不重做页面，不改变业务数据、内容结构、筛选逻辑、交互流程或数据来源提示。

## 优化范围

仅调整 `src/pages/companyList/index.module.less`，原则上不修改 `index.jsx`：

- 左侧企业索引，包括标题、公司数量、搜索框、全局报告筛选、企业序号、企业名称、报告周期和配置按钮。
- 右侧顶部筛选栏，包括当前公司信息、年度和周期下拉框、PDF 预览按钮。
- 右侧报告正文，包括报告封面信息、章节标题、子标题、普通正文、表格、结论、财务分析、治理事项、产业协同、风险隐患、整改事项、生命周期事项和管理策略。
- 配置弹窗与勋章管家浮动入口仅统一字体和基础密度，不改变视觉身份或交互。
- 桌面端、`1050px` 以下布局和 `760px` 以下移动端规则。

## 设计方向

采用“体系化精修”方案：

- 保留现有蓝灰色、暗红强调色和暖白纸张背景。
- 保留报告标题与叙述正文的宋体体系，维持正式报告感。
- 左侧索引、筛选控件、表格、标签和结构化卡片继续使用微软雅黑/苹方等无衬线字体。
- 不新增网络字体、依赖、动画、装饰背景或新的视觉组件。
- 不扩大整体页面尺寸，不显著降低单屏信息量。

## 页面级样式变量

在 Less 文件顶部补充当前页面专用的设计变量，现有主色变量继续保留：

- 报告字体：`"Noto Serif SC", "STSong", "SimSun", serif`
- 界面字体：`"Microsoft YaHei", "PingFang SC", sans-serif`
- 数字字体：继承界面字体，并通过 `font-variant-numeric: tabular-nums` 保持对齐
- 辅助字号：`11px`
- 小正文：`12px`
- 卡片正文：`13px`
- 界面主文字：`14px`
- 报告正文：`15px`
- 卡片圆角：`8px`
- 页面控件圆角：`7px`
- 统一轻阴影：`0 4px 14px rgba(34, 58, 78, .05)`

不把所有字号强制替换为单一值。报告主标题、章节标题和子标题继续保留现有清晰梯度，但删除同层级中没有语义依据的 10px/11px、12px/13px跳变。

## 字体与字号层级

### 左侧企业索引

- “企业索引”保持 20px 标题层级，数量使用 12px 辅助数字，不再单独使用 Georgia。
- 企业名称保持 14px，报告周期由 10px 提升至 11px。
- 企业序号由 Georgia 改为界面字体的等宽数字，保持 11px。
- 搜索框、Select 和配置按钮统一使用界面字体；按钮维持紧凑高度，不扩大列表行高。

### 顶部筛选栏

- 辅助标签统一 11px，当前公司名称统一 14px、600 字重。
- Select 和 PDF 按钮的文字、控件高度与圆角保持一致，减少当前按钮和下拉框的视觉落差。
- 保持吸顶、半透明白底和现有阴影，不改变功能布局。

### 右侧报告

- 报告主标题、章节标题、子标题和叙述正文保留宋体体系。
- 普通正文保持 15px；常规行高收敛至 1.9，卡片正文收敛至 1.75–1.8。
- 表格、标签、来源说明和结构化卡片统一使用界面字体。
- 所有原 10px 的有效辅助信息提升至 11px；装饰性序号也统一为 11px。
- 数字列、日期和百分比启用等宽数字，不再通过 Georgia 制造数字差异。

## 组件一致性

- 财务分析、审计、风险、国资委整改、生命周期和管理策略等卡片统一为 8px 圆角、相同边框灰度与统一轻阴影。
- 同级卡片标题栏统一为 11–13px 的元信息梯度，并使用相近的上下内边距。
- Ant Design `Tag` 在当前页面内统一为 11px；表格统一为 12px，不改变行列结构。
- 来源说明继续使用现有叹号图标模式，字号统一为 11px，不平铺来源文字。
- 红色继续只承担章节锚点、关键结论和风险提示，蓝色继续承担标题、结构和操作，不引入新的强调色。

## 响应式与打印

- `1050px` 以下维持当前左右布局调整方式，只同步字体和控件变量。
- `760px` 以下继续切换为单列报告，结构化卡片允许元信息自然换行。
- 移动端最小有效字号保持 11px，不因空间压缩回退到 10px。
- 不改变现有打印分页规则；打印时保留纸张字体、章节层级和卡片避免跨页规则。

## 数据与异常处理

本次无数据流、接口和状态变更，因此不新增业务异常处理。样式覆盖必须限制在 `companyList` CSS Module 内，避免影响 Ant Design 全局组件或其他路由。

## 验证

- 静态检查确认无 10px 有效文字残留，装饰性内容如确需保留必须有明确例外。
- 检查报告字体与界面字体的使用边界：叙述正文为报告字体，结构化信息为界面字体。
- 检查左侧索引、顶部筛选、报告封面、全部六个章节、配置弹窗和浮动入口。
- 分别在桌面宽屏、约 1050px 和 760px 以下视口进行视觉核对。
- 运行 `git diff --check`、Biome 检查和 `npm run vite.build`。
- 项目现有 `npm run check-types` 因 `tsconfig.json` 无输入且包含已移除的 `esModuleInterop=false` 而失败；该问题不属于本次 UI 精修范围，但最终结果需如实记录。

## 非目标

- 不修改 JSX 结构、业务文案、示例数据、排序和默认筛选条件。
- 不改变页面宽度、侧栏宽度、章节顺序和卡片信息结构。
- 不新增暗色模式、动效、主题切换或第三方字体。
- 不处理 `companyList` 页面之外的全局设计系统。
