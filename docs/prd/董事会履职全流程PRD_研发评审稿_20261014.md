## 1. 背景与目标

董事会履职工作涉及集团董办、一汽股权多个经办角色、董事以及各履职任务负责人。当前项目已具备董事聘任、履职准备、计划与任务、报告、专项任务、履职建议等前端工作台页面，但状态与数据以本地 mock 为主。本需求将目标流程串成可追踪闭环，明确不同角色的入口、页面、字段、操作、任务触发和通知。

### 1.1 业务目标

- 集团董办下发董事推荐函后，相关一汽股权经办人员收到待办并办理聘任事项。
- 聘任事项办结后，依次完成履职手册确认、手册资料更新、履职计划制定与董事确认。
- 董事确认后的计划生成履职任务，由责任人执行；执行信息汇总后支持董事与董办完善并发送履职报告。
- 集团董办可下发董事专项任务，任务完成情况可归集至履职报告。
- 董事可关联前序履职任务提出建议，由一汽股权董办分派责任人落实并回写办理结果。

### 1.2 本期范围

纳入本 PRD 的流程和页面：

1. 工作台首页 `/boardGovernance/home`：按角色呈现董事聘任、履职准备、履职计划制定、履职任务管理、履职报告完善、履职建议落实等任务组。
2. 董事聘任 `/boardGovernance/appointment`：推荐函下发与聘任任务办理。
3. 履职准备 `/boardGovernance/preparation` 及董事准备详情：履职手册确认、资料更新触发、年度计划编制与推送。
4. 履职任务 `/boardGovernance/duty-tasks`：董事计划确认、责任人执行、手册资料提交。
5. 履职管理 `/boardGovernance/management/:directorId`：履职报告查看、编辑、发送与接收。
6. 董事专项任务 `/boardGovernance/director-special-tasks`：集团董办建任务、选董事、下发。
7. 履职建议 `/boardGovernance/duty-suggestions` 及详情：董事发起、董办分派、责任人落实。

履职评价、会议管理、治理资料、角色配置等代码中其他菜单不在本次流程需求范围内；本 PRD 只说明与本流程的入口或依赖，不扩写其业务规则。

### 1.3 交付边界

本 PRD 描述产品行为、页面字段、流程状态与验收口径。当前代码可见的交互不等于生产实现：角色切换是演示视角，本地状态不是持久化服务，消息图标和成功提示不代表已接入真实钉钉。后端接口、钉钉应用配置、附件存储、组织通讯录数据结构需在技术方案或接口设计阶段落定。

## 2. 角色与权限视角

| 角色/办理视角 | 目标职责 | 主要入口 | 目标可见/可办范围 | 当前代码情况 |
|---|---|---|---|---|
| 集团董办 | 下发董事推荐函；下发董事专项任务 | 董事聘任、董事专项任务 | 发起推荐函、选择管理范围内董事并下发专项任务；查看相关任务状态 | 主角色切换器存在；推荐函与专项任务表单存在；当前为前端模拟 |

| 一汽股权-数字化 | 配置系统权限 | 工作台董事聘任任务 | 办理系统权限配置并提交 | 当前聘任状态含系统权限步骤；无独立子角色切换 |
| 一汽股权-董办 | 工商变更、履职手册确认、履职计划、履职报告与建议分派 | 工作台、聘任、准备、管理、建议 | 办理分配给董办的事项；确认手册及计划；维护/发送报告；分派建议 | 页面流程有相关能力；聘任数据中工商变更任务的负责人标签当前为审计风控与法务部，需业务确认映射 |
| 董事 | 确认履职计划；执行个人履职报告编辑发送；提出履职建议 | 工作台、履职任务、履职管理、履职建议 | 只处理与本人相关计划、报告和建议 | 有董事主角色；部分页面通过演示 ID 过滤，不应视为生产鉴权 |
| 履职任务责任人 | 更新手册资料或填报计划任务执行情况 | 工作台、履职任务 | 只办理分派给本人/部门的任务 | 当前以负责人名称/部门参数模拟，需接入真实用户权限 |

**目标权限原则：** 页面、任务、详情和可执行按钮应按真实用户角色、责任部门、责任人及业务数据范围控制。前端隐藏按钮不能代替服务端权限校验。该原则作为目标需求，具体权限源和组织关系接口待技术设计确认。

## 4. 端到端业务流程

### 4.1 主链路：聘任、履职准备、计划与履职报告

| 顺序 | 发起角色 | 触发动作 | 任务/消息接收方 | 目标结果与下一步 |
|---|---|---|---|---|
| 1 | 集团董办 | 在董事聘任页填写并下发董事推荐函 | 一汽股权对应经办人员收到待办；按目标要求发送钉钉提醒 | 建立聘任案件；生成董事简历、系统权限配置、工商变更办理事项 |
| 2 | 一汽股权人力 | 打开董事简历任务，填写并提交 | 聘任案件 | 对应步骤完成；等待其它聘任步骤 |
| 3 | 一汽股权数字化 | 打开系统权限配置任务，填写并提交 | 聘任案件 | 对应步骤完成；等待其它聘任步骤 |
| 4 | 一汽股权董办 | 打开工商变更任务，填写并提交 | 聘任案件 | 当三个目标办理事项全部提交后，创建履职手册确认任务 |
| 5 | 一汽股权董办 | 打开履职手册确认任务，检查董事履职手册目录 | 履职准备详情 | 手册确认进入资料更新/推送环节 |
| 6 | 一汽股权董办 | 点击“定期发起资料更新” | 对应资料责任人收到手册资料更新任务 | 责任人逐项补资料并提交；全部资料提交后，手册表状态为“已提交” |
| 7 | 一汽股权董办 | 所有相关资料均已提交后，预览并推送手册，确认推送 | 董事收到手册；董办收到履职计划制定任务 | 进入年度履职计划编制 |
| 8 | 一汽股权董办 | 在履职计划制定任务中新增计划并提交 | 董事收到年度履职计划确认任务 | 计划送董事确认 |
| 9 | 董事 | 查看计划明细、选择计划并提交 | 一汽股权董办收到任务完成提示；按目标发送钉钉消息 | 计划进入可生成年度计划/履职任务的状态 |
| 10 | 一汽股权董办 | 在年度履职计划生成页选中计划明细并确认生成任务 | 各计划对应责任人收到履职任务 | 责任人进入履职任务页填写具体办理信息 |
| 11 | 责任人 | 填写实际办理信息、说明、附件并提交完成 | 董事本人、综合董办、综合办公室收到日程/差旅安排通知；董办和董事收到履职报告完善任务 | 任务办理信息归集，报告任务产生 |
| 12 | 一汽股权董办、董事 | 分别编辑报告，选择接收人员并确认发送 | 所选人员 | 报告完成发送，发送状态和接收信息可追踪 |

### 4.2 支线 A：集团董办下发董事专项任务

1. 集团董办进入 `/boardGovernance/director-special-tasks`，点击“下发董事专项任务”。
2. 填写任务名称、人员范围、工作分类、时间、地点、工作内容、预期达成目标和相关材料。
3. 点击“确认下发”后，任务发送给一汽股权综合管理部董办、办公室及所选董事；按目标要求开展日程等安排与完成情况确认。
4. 任务完成结果同步进入董事履职报告的履职事实/报告内容。

当前代码中的“专项任务”名称可创建列表记录，工作分类、董事多选、时间地点内容目标和附件均有表单字段；当前尚未创建面向董办/办公室/董事的工作台任务，也未实现完成确认和报告同步。

### 4.3 支线 B：董事发起履职建议

1. 董事在 `/boardGovernance/duty-suggestions` 新建履职建议，选择一个前序履职任务并填写建议内容。
2. 提交后，一汽股权董办在工作台“履职建议落实”任务组收到任务。
3. 董办在建议详情指定责任部门、责任人和期限并下发。
4. 对应责任人进入建议详情，填写落实方案、进度、反馈说明、落实结果及佐证材料并提交。
5. 建议状态与办理记录更新；办理结果用于履职建议闭环和后续履职报告归集。

当前代码已有“待董办补充、待落实、办理中、已关闭”等建议状态、建议与前序任务 ID/快照关联、责任人办理视角与记录；生产任务分派及通知仍需接入真实任务与用户体系。

## 5. 页面级需求与字段

### 5.1 工作台首页 `/boardGovernance/home`

**页面用途：** 汇集当前角色待办，提供任务分类、所属部门/任务组、办理进度及“去执行”入口。首页中的“董事聘任、履职准备、履职计划制定、履职任务管理、履职报告完善、履职建议落实”等分类对应不同阶段任务。

**任务卡/任务列表信息（以当前实现为基线）：**

- 任务标题、任务说明/描述、任务状态、截止时间。
- 任务分类、所属部门或任务组、负责人/责任人（数据有值时展示）。
- 该分组任务总数、已完成数、待办数；资料组展示资料项总数和已提交数。
- 操作入口：“去执行”或进入相应业务页。

**角色可见分类：**

| 角色 | 目标显示内容 |
|---|---|
| 集团董办 | 董事推荐函下发、集团专项任务；本流程中不显示一汽股权内部办理任务 |
| 一汽股权 | 董事聘任办理、履职手册资料更新/确认、履职计划制定、履职任务管理、履职报告完善、履职建议落实 |
| 董事 | 年度履职计划确认、本人履职报告完善；可进入履职建议 |

**差异：** 当前首页实现的董事专项任务作为独立菜单；工作台董事聘任组取当前各状态案件展示；存在硬编码董事和任务数据。当前代码中的任务分类不完全等同于用户口述的 Tab，UI 需产品/设计确认最终是横向 Tab、任务分类导航还是同页分组。

### 5.2 董事聘任 `/boardGovernance/appointment`

**列表用途：** 查看聘任案件及当前办理阶段。当前页面可由集团董办下发推荐函，案件详情通过抽屉打开。

**列表字段（代码/数据可见）：** 案件编号、董事姓名、任职企业、职务、推荐函编号、推荐函文件名、当前负责人、接收人、截止时间、当前步骤/状态、查看详情。

**推荐函 Modal 字段：**

| 字段 | 当前交互/约束 |
|---|---|
| 推荐函附件 | 可选；支持 PDF、DOC、DOCX；单文件；当前前端不上传服务器 |
| 推荐函编号 | 必填；可手动填写或在上传后由识别结果预填 |
| 拟任董事 | 必填 |
| 文件名称 | 必填 |
| 印发时间 | 必填；当前为文本输入 |
| 任职说明 | 必填，多行文本 |
| 操作 | 取消、下发；识别结果可编辑 |

**聘任任务字段/步骤：** 当前聘任状态包含“待上传董事简历”“待配置系统权限并纳入组织架构”“待完成工商变更”“已完成”。目标流程对应人力、数字化、董办三项办理任务；每项任务的专属填写字段尚未在统一代码页面里完整呈现，需业务确认后补充。本需求要求每项任务详情至少承载该事项的办理内容与提交操作，不在本稿臆造具体简历字段或权限清单。

**触发规则：** 点击下发后建立案件及三项办理任务，给一汽股权经办人员生成站内待办并发送钉钉提醒；三项全部提交后生成董办的“履职手册确认”任务。

### 5.3 履职准备与履职手册

#### 5.3.1 董事准备详情 `.../preparation/directors/:directorId?tab=handbook`

**页面用途：** 董办核对董事手册目录、查看各资料状态、发起资料更新、预览和推送手册。

**董事手册表字段（代码数据）：** 资料编号、类别、资料名称、责任部门、责任人、更新频次、状态；更新任务过程中可显示提交时间、已上传文件及办理状态。

**操作与规则：**

## 7. 状态与规则

### 7.1 本流程状态（目标）

- 聘任案件：待推荐函下发 → 董事简历办理 → 系统权限配置 → 工商变更 → 已完成。阶段顺序与每步“提交”是否需要审核以具体业务规则为准。
- 履职手册资料：待发起/待提交 → 已提交；全部适用项提交后开放预览并推送。
- 履职计划：草稿 → 已提交 → 董事待确认/调整 → 已确认 → 已生成履职任务。
- 履职任务：待执行/办理中 → 已提交/待确认（如适用）→ 已完成。状态语义、提交人和完成确认人待业务确认。
- 履职报告：待完善 → 已保存 → 已发送；董办接收流程（若存在）独立记录接收状态。
- 履职建议：待董办补充 → 待落实 → 办理中 → 已关闭。
- 专项任务：待办理 → 办理中 → 已完成。具体任务确认角色待确认。

### 7.2 必须遵守的流程门槛

1. 三项聘任任务全部提交后，才生成手册确认任务。
2. 所有对应手册资料提交后，才允许确认推送手册。
3. 手册推送确认后，才创建年度计划制定任务。
4. 董办提交计划后，董事才能收到对应确认任务。
5. 董事提交计划确认后，董办才可针对已确认明细生成履职任务。
6. 履职建议下发前必须明确责任部门、责任人；目标描述中还包含期限，代码现状要求需以实际校验核实。
7. 报告确认发送前至少选择一名接收人（当前代码已有校验）。

## 9. 异常与边界

- 当前地址所指案件、董事、计划、报告或建议不存在时，页面展示清晰的无数据状态并提供返回列表入口。
- 尚未完成前置任务时，不生成下游任务；页面应说明阻塞原因。
- 附件选择/上传失败时不得将任务标为已提交；生产上传接口与失败提示需技术方案明确。
- 重复点击提交或网络重试不得重复生成任务、重复发送报告/通知；幂等键和去重策略由接口设计明确。
- 某个钉钉通知失败时，业务数据状态与通知状态应可区分；重发策略待确认。
- 用户无权限访问任务详情或跨角色办理时，应拒绝访问并返回无权限提示；服务端必须校验。

以上异常项中，项目代码未完整实现的均为目标产品要求，需在研发方案评估服务端支持方式。

## 10. 验收标准

### 10.1 角色与入口

- 集团董办可进入董事聘任并发起推荐函，可进入董事专项任务并下发任务。
- 一汽股权人力、数字化、董办及办公室各自仅看到分派给本角色/部门的任务；生产角色边界需与业务确认表一致。
- 董事只看到本人年度计划确认、本人报告及履职建议入口。
- 工作台点击任一任务后进入对应对象详情，返回后可回到原任务上下文。

### 10.2 主链路

- 下发推荐函后生成三项聘任任务；每项提交后进度可见；三项均提交后生成手册确认待办。
- 发起资料更新后相关责任人收到任务；全部适用资料已提交前不能确认推送；全部提交后状态与推送入口正确。
- 确认推送手册后生成董办履职计划制定任务；提交计划后生成董事确认任务；董事提交后生成可供董办年度计划生成的已确认明细。
- 生成年度计划任务后，对应责任人收到任务；责任人提交后，任务状态及报告可用履职事实一致。
- 所有履职任务满足完成规则后，董事和董办分别收到报告完善待办；报告可编辑、选择接收人并确认发送，发送状态可追踪。

### 10.3 支线闭环

- 专项任务表单具备目标字段和分类选项；确认下发后向董办、办公室、选中董事生成待办；完成结果能在对应董事履职报告中查到。
- 董事履职建议必须关联前序履职任务；董办能分派责任部门/人/期限；责任人能提交落实结果；建议状态与办理记录更新，结果进入报告归集范围。

### 10.4 代码与产品一致性

- 页面字段和状态以本 PRD 的最终评审结论为准；当前硬编码演示 ID、mock 角色和本地状态不得作为生产业务规则。
- 目标路由可直接访问并保持角色授权；页面路径变化时任务链接同步更新。
- 钉钉通知仅在真实集成成功后才展示成功结果；失败不得误报已送达。
