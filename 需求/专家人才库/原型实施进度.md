# 专家人才库原型实施进度

## 客户最新流程改造（2026-09-05）

- 入库管理新增“初始推荐名单/候选专家池”：不设置7类、5类或固定人数，支持新增、批量选择、CSV文本导入演示和转合作邀请。
- 推荐名单字段覆盖批次、姓名、单位、职务、手机号、来源、推荐部门、推荐人、关联项目、领域、理由和状态；客户实际名单待后续手工导入。
- 入库邀请补充合作邀请函编号、模板和有效期；短信仅用于通知专家进入小程序查看。
- 专家提交完整履历后，由需求部门填写正式《专家入库申请表》；缺少申请表不能发起审批。
- 补充资料完整性、准入条件、关联与合规三重校验详情，每项均需经办人手工确认，系统不自动决定入库。
- 审批链改为：股权运营部完成资料与申请核对 → 在 `/djghome` 原任务列表由分管领导线上审批 → 审批通过后进入待签发聘书 → 公司与专家签订3年聘书后正式入库；退回则由发起人修改后重新提交。
- 专家档案新增聘期管理：聘期结束或年龄上限前90天预警；续聘复用分管领导审批，审批通过后签订新的3年聘书；普通专家65周岁、高层次专家70周岁，年龄临期可主动解聘并留痕。
- “专家调用审批”改为“专家调用申请受理”，办理主体为股权运营部；受理通过后才能匹配。
- 调用匹配增加系统推荐排序、推荐依据、回避校验提示、需求部门确认/调整理由，以及股权运营部锁定排期。
- 专家逻辑仅在 `/djghome` 与 `expertTalent` 路由按需加载，`/gzthome` 不展示专家任务。
- 未修改现有小程序文件，未执行 Git；本轮只允许普通 Vite build。

## 本轮流程补全（2026-09-04，覆盖下文早期范围）

- 需求方统一 PC 调用，小程序移除普通服务申请导航并拦截旧路由。
