日期：2026-10-22  
版本：V2，依据用户本轮确认修订。

## 3. 入库与运营配置联动

### 3.1 履历字段调整

| 履历字段 | 控件与来源 | 规则 |
| --- | --- | --- |
| 职务 / 职称 | 可搜索单选，来自运营管理维护的职务/职称字典 | 不允许在履历页面自由输入或回车新增；目前运营页没有独立字典，需要补充维护入口 |
| 专家类别 | 可搜索单选，来自运营管理“标签与分类”的专家类别字典 | 如产业研究、技术研发等，表示专业类别，不作为内外部身份 |
| 主领域 | 可搜索单选，来自运营管理“标签与分类”的主领域字典 | 保存稳定编码；用于档案检索、调用匹配，不保存拼接自由文本作为主键 |
| 专家内外部身份 | 选择，来源与运营咨询费用标准的专家来源一致 | 外聘/外部统一显示和编码映射；原推荐来源单独保留，不能与计费身份混用 |
| 计费等级 | 按所选身份筛选有效费用标准的职级/等级选项 | 以运营“专家咨询费用标准”为唯一计费依据；不从履历职务文本自动猜测金额 |

职务/职称是履历信息，计费等级是费用匹配信息。即使显示名称相同，也通过配置映射或明确选择关联，避免同职称不同专家身份套用同一价格。职务/职称字典可以关联费用等级以便带入，但最终必须命中有效标准。

运营维护端可以新增、编辑、停用字典；履历录入端只能选择已启用项。缺少选项时提示联系运营维护，不开放绕过字典的自由输入。停用项保留历史名称和引用，新的录入不能选用；历史修改时如仍使用停用值，提示重新选择，不静默删除。

历史自由文本需进行字典映射。未匹配的原值保留显示并标记“待规范”，不能自动强行转成默认类别或计费等级。原入库申请、在库档案和调用均使用同一配置数据源。

### 3.2 结算资料

在入库资料中增加“计费与结算信息”区域，并在在库专家档案中提供对应查看/维护入口：

- 证件类型、证件号码：关联既有入库身份资料，避免同一人重复维护冲突的证件值。
- 专家内外部身份、计费等级/标准关联：来自运营费用标准，支持身份和等级联动选择。
- 收款户名、开户行、收款账号；银行联行号仅在实际表单确有需要时补充。
- 账号确认状态、确认人、确认时间及确认版本；由人力确认。

本期设计允许入库时填写账号资料，账号暂缺可补充，不以账号已确认作为能否聘任入库的条件；月度批次完成确认/导出前，必须补齐并确认。此项为避免阻塞入库的默认设计，尚未作为用户明确确认的强制时点。

证件、账号页面脱敏，完整值只对受权角色开放。账号变更后确认状态失效，需重新确认；已经确认的报销/汇总使用账号版本快照，不能随档案变化自动覆盖。

### 3.3 前序流程衔接修正

现有代码中，新入库档案写入store.experts，调用页仍读取静态data.js专家。设计要求入库、在库列表、调用选择、匹配均读取统一专家集合。

入库聘书写入“已生效/sentAt”，在库抽屉可调用条件读取“已签署/signedAt”，两处应统一正式聘任生效判定。新入库符合聘任与风险条件的专家，必须能立即参与调用选择。

既有入库资料与专家档案通过expertId及原入库记录ID稳定关联。正式结算数据不得用演示函数补造证件号码。

## 4. 本期业务流程

```text
运营配置字典与专家咨询费用标准
  → 入库履历选择、计费身份与结算资料
  → 入库审批、聘任生效
  → 调用申请、确认专家、排期服务
  → 正式咨询记录提交、履约评价完成
  → 原调用人录入税前报销，保存草稿或提交审批
  → 部门负责人审批通过
  → 财务负责人审批通过
  → 如超标，再由分管领导审批通过
  → 报销已审批
  → 月度归集
  → 人力确认账号、汇总资料复核
  → 月度汇总确认与导出
```

审批按部门负责人、财务负责人顺序办理，超标再追加分管领导。账号确认与汇总复核承接原月度表要求，仅处理本系统资料完整性和税前金额，不扩展外部财务流程。

评价完成是开启报销的业务状态门槛，不再新增独立验收条件。单据提交仍校验专家、金额、服务明细和来源关联的基本完整性；调用现有正式咨询记录作为来源材料引用。

报销权限锁定原调用申请人ID，不通过姓名或当前部门文本判断。其他人可按权限查看或审批，不能直接代原调用人新建或提交；本期没有新增代办流程。

已评价完成后允许复评，但复评不会重复生成报销单，也不会重置已有单据。调用完成与费用审批分开，报销审批完成后调用状态仍为已评价完成。

专家后续到期或解聘，历史已完成的有效调用仍可办理报销；不以当前是否可新增调用重新否定历史服务。

## 5. 调用抽屉“调用报销”Tab

保留原“需求与轨迹 / 推荐匹配与排期 / 成果与验收”，仅在已评价完成时新增可办理的“调用报销”。

### 5.1 展示结构

1. 顶部：调用编号、项目、调用完成状态、报销单状态、关联批次。
2. 来源信息：专家、内外部身份、计费等级、证件脱敏值、原调用申请人和部门、申请单/正式咨询记录入口。
3. 服务明细：一个或多个实际服务日期、实际时长、计费天数、适用标准及差异原因。
4. 金额区：标准税前应付、申请税前金额、超标金额和比例、超标原因与附件。
5. 结算资料：收款账号脱敏值及确认状态；资料缺失时提供补充入口。
6. 审批轨迹：负责人、处理时间、意见、退回记录；展示是否需追加分管领导。
7. 底部：保存草稿、提交审批、退回后重新提交；提交后以只读详情为主。

### 5.2 字段规则

| 字段 | 规则 |
| --- | --- |
| 单据编号 | 服务端生成BX＋建单年月＋三位流水；全库唯一、不可手改，不作为数据库唯一内部主键 |
| 调用编号/项目 | 从当前调用带入，只读；名称展示，关联使用稳定taskId |
| 专家 | 从当前调用最终expertId带入，只读；不能从全库重新任选专家 |
| 内外部身份/计费等级 | 从专家档案及有效运营费用标准带入，保留标准ID和版本 |
| 证件号码 | 从安全身份资料关联，脱敏展示 |
| 服务日期 | 从正式咨询记录带入参考值，允许调用人按实际服务填写多日明细 |
| 实际时长 | 可参考成果记录中的分钟数，修改应保留原因；预计时长不直接等于报销时长 |
| 计费天数 | 以天为展示单位，步长0.5；0.5天＝1个半天，与实际分钟、折算过程分别保存 |
| 计费标准 | 读取运营“专家咨询费用标准”；单位元/人/半天，本期报销比较口径必须明确为税前 |
| 标准应付金额 | 按选定标准、实际计费明细和适用折算规则计算税前额度 |
| 申请报销金额 | 调用人输入税前金额，金额到分；不录入税后金额，不做税后反算 |
| 超标原因 | 申请税前金额超过标准税前应付时必填，允许补充依据附件，并追加分管领导审批 |
| 发起人/需求部门 | 保留原调用申请人及部门ID；不能因当前登录用户或组织变化覆盖原申请归属 |
| 收款账号/确认 | 从专家结算资料引用，展示版本和确认结果；变更需重新确认 |
| 审批信息 | 审批实例、节点负责人、结果、意见、时间及提交版本 |
| 汇总信息 | HZ编号、结算月、批次状态、纳入时间 |

本期不展示可编辑的个人所得税、增值税及附加、实发金额，也不自动带出“外部=代扣、内部=不代扣”的税务标识。后续如需保留原报表税务列，统一留空或显示“本期未计算”，不填写0、不把税前金额当作实发金额。

### 5.3 单据数量与无偿调用

一任务一专家仅允许一张有效正常结算单。保存草稿、重复点击、复评、再次打开详情都复用原单据。退回在同一单据保留修订版本并重提，不生成重复BX。

如单据作废，保留原编号与轨迹，再次办理需要明确作废替代关系；任何时刻仍只允许一张有效正常单据。本期不提供多专家拆单或分期功能。

调用明确为无偿时，展示“无偿调用，无需费用结算”，不生成BX，不计入费用汇总笔数。预算为0是否必然等于无偿，应使用已有业务定义；如不等价，需要独立无偿标识，不能只凭预算数值误判。

## 6. 统一计费与税前超标比较

### 6.1 配置唯一来源

入库计费等级、调用申请测算、最终报销校验均读取运营专家咨询费用标准。停用标准不进入新选择，历史标准保留快照。内部、外部使用同一报销和付款方式，不设计额外工资路径。

标准至少结构化维护：标准ID、专家内外部身份、计费等级、服务形式、工作/业余条件、半天标准金额、金额口径、启停状态、有效期及版本。原页面说明中的工作/业余金额不能只藏在备注中。

选定最终专家后，申请和报销不能继续沿用另一位意向专家的旧档位。报销的标准匹配结果应由当前专家的身份、计费等级及适用服务条件产生。

### 6.2 天数和半天标准

完整半天计费时：

```text
标准税前应付＝税前半天标准×计费天数×2
例如：1000元/半天，计费0.5天，标准应付1000元。
```

申请预计小时、成果实际分钟、报销计费天数为不同字段。不得用“小时数×半天标准”或“0.5天×半天标准”直接计算。

旧系统还包含不足2小时按半天标准折半、2—4小时按一个半天、超过2天部分按50%计算。这些不是单纯单位换算。现阶段作为现有计费规则保留说明，不默认为本轮已经批准保留或删除；第11节单独列明。若保留，不足2小时通过折算系数体现，不把界面计费天数步长悄悄改为0.25天。

多日明细应按同一调用约定的合计规则核算，不能每新增一行都重置超过2天的累计门槛。

### 6.3 税前口径转换

已确认：申请金额和超标比较统一税前。本期不做税务模型，不能自动将原税后费用标准反算成税前。

已确认现有标为税后的运营标准，由业务维护确认后的税前金额，再供报销匹配。本系统不直接沿用原数值当作税前标准，也不做反算；未完成税前金额维护的标准不得供新的正式报销使用，历史记录继续保留原口径快照。

标准不足、未启用、口径不明或无法唯一匹配时提示维护配置，不默认金额0，不让调用人随意手改标准绕过审批。

### 6.4 超标与预算

超标条件＝申请税前金额＞标准税前应付；等于标准属于普通单。超标原因必填，审批路线增加分管领导。申请金额或服务明细改变导致超标判定变化时重新计算并按新版本走审批。

预算可以展示参考差额，但本轮未确认独立超预算审批节点；不擅自新增业务阻断或审批。费用标准变更不回算历史已审批单据。建议以正式提交报销时匹配的有效规则保存快照；是否锁定服务日/申请日费率可后续细化。

## 7. 审批与状态

### 7.1 单据审批

```text
草稿 → 审批中 → 已审批
          └→ 已退回 → 修改 → 重新提交
```

审批中展示当前节点，可细分“部门负责人审批中 / 财务负责人审批中 / 分管领导审批中”。普通单两位负责人都必须通过，超标单还必须分管领导通过，任何必需节点未通过不得纳入月度汇总。

申请人不能自行把状态改成已审批。审批意见、操作人、时间、提交版本完整留痕。变更金额、服务、专家关联、标准等关键内容后原审批不能直接沿用；审批中默认锁定编辑，退回后修改。

已确认顺序为“部门负责人→财务负责人→超标时分管领导”。部门通过后才进入财务节点，财务通过后普通单变为已审批，超标单进入分管领导节点；不采用并行会签。同一人兼任多个角色时是否允许一人完成两节点，沿用公司现有工作流授权规则，不通过前端角色文字判定。

### 7.2 审批与汇总分开

审批状态：草稿、审批中、已退回、已审批、已撤回/已作废（按已有工作流支持）。

汇总状态：未汇总、已纳入批次、批次已确认/已导出。已纳入批次后审批状态仍是已审批。

调用履约状态独立保持已评价完成。本期不新增付款中、已付款、归档中或已归档的业务动作，也不把审批或导出解释为财务付款完成。

## 8. `/zj/pool`费用结算工作区

### 8.1 报销台账

筛选：调用申请人、需求部门、专家、项目、服务日期、审批状态、结算月、汇总编号。

列表：BX编号、调用编号、专家、内外部身份、项目、调用人/部门、服务日期范围、标准税前应付、申请税前金额、超标标识、审批状态、账号确认状态、汇总编号。

动作：查看报销详情、查看原调用/正式咨询记录、按权限审批和退回、跳转批次、导出授权数据。不允许从台账脱离调用自由新建报销。

### 8.2 月度汇总列表

列表：HZ编号、结算月份、生成时间、单据笔数、去重专家人数、税前报销金额合计、账号待确认数、流程状态、最后操作人。

批次编号HZ＋年月，一月一张整体表。重试定时任务复用本月批次，未确认阶段刷新保留版本及差异，不新建相同编号的重复批次。

详情分为汇总明细、账号确认、处理轨迹。每行一张BX，多日服务可展开；不能因有多个服务日重复累加整单金额。

明细字段：BX编号、专家、证件脱敏值、内外部身份/计费等级、项目、调用编号、调用人/部门、服务日期、税前报销金额、付款账号及确认状态、调用申请、正式咨询记录/交付物。

本期合计为单据笔数、税前金额合计，可另显示专家人数。原需求的个税、增值税及附加、实发金额列及合计不计算；如为了财务模板保留列，空值明确表示本期未计算，不参与合计。

### 8.3 汇总规则

归集条件：截至配置结账时间，报销审批已经全部通过、未作废、金额与基础资料有效、未进入其他有效批次。包含往期服务但本期才审批通过的补报单。

- 默认每月最后一日结账，具体时刻可配置，统一使用Asia/Shanghai；截止后执行归集。
- 截止后审批完成的进入下月，不以服务发生月强制回填已确认批次。
- 定时任务重复运行、失败重试、人工刷新需去重，同一有效BX不得进入两个有效批次。
- 金额或身份等基本资料异常进入异常清单；账号未确认可以先进入待确认批次。
- 未完成账号确认的明细不能完成批次确认/正式导出；可查看和导出带未确认标记的预览清单。
- 已确认或正式导出的批次冻结内容，迟报默认次月；不直接插入新行。批次退回修改需保留版本、重新确认及导出记录。
- 当月无可结算报销时记录任务执行结果和空态，不生成空的正式批次。

批次内部处理建议为“已生成→待账号确认→待汇总复核→已确认”，导出另记录次数、版本、操作人及时间。账号由人力确认；复核只检查来源、审批、账号、税前金额及合计。本轮不展开这些内部节点与外部平台的职责映射，也不新增税务复核。

人力按专家ID核对收款资料，保存确认版本；改账号必须重确认。汇总复核不替代逐单财务负责人审批，不再次擅改已审批金额；发现差异退回来源单据更正并重审。

金额按分存储与求和，批次税前合计必须等于明细税前合计。导出引用真实文件ID及正式版本，不仅提供本地附件名称。

## 9. 数据关联和历史保留

```text
专家Expert → 调用CallTask → 一张有效报销Reimbursement
报销Reimbursement → 多行实际服务ServiceLine
月度批次MonthlyBatch → 多笔批次明细BatchItem → 报销Reimbursement
```

| 对象 | 核心字段 |
| --- | --- |
| 运营字典 | 字典编码、名称、启停、版本；职务/职称、类别、主领域分别维护 |
| 费用标准 | 标准ID、来源身份、计费等级、形式、时段条件、税前半天金额、有效期、版本 |
| 专家 | expertId、原入库ID、履历字典编码、身份及计费等级关联、证件安全引用、结算账号及确认版本 |
| 调用 | taskId、最终expertId、原调用人ID及部门ID、项目、服务/咨询记录、完成评价 |
| 报销 | 内部ID、BX、taskId、expertId、调用人ID、服务明细、标准及资料快照、税前金额、超标原因、审批实例/版本/通过时间 |
| 汇总 | 内部ID、HZ、结算月、截止时间、版本、状态、生成及操作轨迹 |
| 汇总明细 | 批次ID、报销ID、批准税前金额、账号确认版本、来源文件版本 |

报销编号、汇总编号为唯一业务标识，另设内部ID。历史字典、费用、账号版本不能因运营编辑而丢失。一个调用一张有效报销、一个报销一个有效批次由后台唯一约束和事务保证，不能只靠按钮禁用。

本期不为尚未开展的外部付款交易、税务模型、回调事件等扩展实体或接口。

## 10. 本期范围与验收

### 10.1 包含

1. 运营职务/职称字典及现有类别、主领域与履历选择联动。
2. 入库计费身份、计费等级、结算资料及在库档案关联。
3. 专家统一数据源、聘任生效判断、统一运营费用标准读取。
4. 调用人发起税前报销、多日服务明细、超标原因与审批。
5. 财务负责人、部门负责人审批，超标追加分管领导。
6. 看板的资源概览/费用结算工作区、报销台账、月度归集、账号确认、汇总复核及导出。

### 10.2 暂不包含

专家端报销、任意经办人代办、多专家或分期结算、税后反算、个税及增值税/附加模型、实发计算、内部工资发放分流、外部财务API、付款/凭证/归档回传。

本期不研究税务法规模型或外部接口契约，不将这些内容作为当前页面开发的前置确认任务。

### 10.3 验收重点

- 履历三个指定字段为运营字典选择，录入端不能自由新增；停用项不供新选择，历史仍可显示。
- 身份/计费等级关联有效运营标准，专家新入库后可在调用中选择，不继续读取静态专家。
- 只有原调用人能建单、编辑并提交，审批角色不能因能看单就代调用人提交。
- 未评价完成不可报销，评价完成即可办理，不增加独立验收；复评不生成重复单据。
- 一调用一专家一有效单，多日服务不拆成多张报销；无偿不生成BX。
- 0.5天按一个半天匹配金额；税前录入、税前超标比较；税务与实发不填假0值。
- 普通单部门与财务负责人均通过，超标还需分管领导；退回重提保留版本与轨迹。
- 运营标准改动不回算已审批单据；标准口径不明时不能无依据套用。
- 已审批未汇总的历史补报能归入当月；重试、刷新、并发归集不重复。
- 账号变更重确认；批次明细与税前合计相等，确认后内容冻结；导出记录版本及操作人。
- 导出后仍不显示为已付款或已归档。
