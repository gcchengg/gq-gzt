# 专家人才库流程与页面功能说明

更新日期：2026-09-07

## 0. 客户最新流程口径（本节优先于下文早期描述）

### 0.1 入库主流程

```text
需求部门推荐候选人员
  → 股权运营部维护“初始推荐名单/候选专家池”
  → 生成并发送《专家合作邀请函》
  → 短信仅通知专家到小程序查看
  → 专家同意邀请并完整提交履历
  → 需求部门填写正式《专家入库申请表》
  → 系统展示完整性、准入、关联合规三重校验
  → 股权运营部逐项人工确认并完成核对
  → 发起分管领导线上审批
  → 分管领导审批通过
  → 公司与专家签订3年聘书，经办人登记聘书信息
  → 正式入库
```

当前方案不设置总办会。分管领导审批通过后进入“待签发聘书”，公司与专家完成3年聘书签订并由经办人登记后，专家才进入“已正式入库”；审批退回则由发起人补充或修改后重新提交。

客户流程图中的“7+5”仅指当前已掌握的两批理想候选人员，不是专家类别、固定人数、名额或配额。系统不设置“7类/5类”字段和人数校验，实际名单待页面完成后手工导入。

### 0.2 调用主流程

```text
需求部门填写专家调用申请
  → 股权运营部在 /djghome 原任务列表进行“专家调用申请受理”
  → 受理通过后进入匹配
  → 系统展示推荐排序、推荐依据和回避校验提示
  → 需求部门确认或调整人选并说明理由
  → 股权运营部协调专家和需求部门、锁定排期
  → 生成专家邀约并准备承诺书
  → 专家服务、提交成果
  → 需求部门进行咨询成果确认
  → 评价、结算和后续回溯
```

“专家调用申请受理”不是领导审批，办理主体固定为股权运营部。系统推荐和回避结果只提供辅助信息，不自动决定专家人选。

### 0.3 当前入库管理页签与操作

- **初始推荐名单：**支持新增候选人、批量选择、CSV文本导入演示，以及将待邀请人员批量转为合作邀请。字段包括批次、姓名、单位、职务、手机号、来源、推荐部门、推荐人、关联项目、领域、推荐理由和状态。
- **入库办理：**查看合作邀请函编号、模板、有效期、专家在小程序填写的全部资料、需求部门入库申请表、三重校验及分管领导审批状态。
- **短信通知记录：**记录短信接收人、手机号、内容、时间和模拟发送状态。短信只通知专家进入小程序，不替代正式合作邀请函。

需求部门入库申请表至少包括关联项目、入库必要性、专业能力评价、建议专家类别、建议专业等级、建议承担角色和需求部门负责人意见。缺少完整申请表，或三重校验尚未逐项人工确认，均不能完成核对或发起分管领导审批。

### 0.4 `/gzthome` 隔离约束

专家人才库业务入口和审批/受理组件只在 `/djghome` 或 `expertTalent` 系列路由中按需加载。`/gzthome` 使用原任务卡片、原默认选中项和原业务逻辑，不初始化专家本地数据、不展示专家任务。

本文说明本轮修改后的角色分工、流程顺序、页面职责、操作位置及原型边界。业务规则与当前实现分开描述，不将模拟提示视为真实后台能力。

## 1. 项目范围和当前状态

### 最新工作台入口调整

专家审批已融入 `/djghome` 原有任务卡片与列表，不再额外显示独立审批区或角色切换控件。以下早期章节提到的“切换演示角色”不再适用。

- 入库审批：`/djghome?task=expertEnrollmentApproval`。
- 调用审批：`/djghome?task=expertCallApproval`。
- 点击任务记录打开审批详情，查看申请、历史轨迹并填写意见，通过或退回后更新业务记录及待办数量。
- 无待审批记录时展示空状态，不生成虚假待办。
- 真实登录审批权限仍待对接，详情中明确提示本地原型办理。
- `/gzthome` 不加载专家审批模块、不改变原有任务逻辑。

- 需求方统一在 PC 发起专家调用。
- 小程序仅服务受邀专家，办理入库、任务确认、成果交付及个人服务事项。
- 不再开放普通用户通过小程序提交专家服务需求的入口。
- PC 页面采用项目 React 代码，六个专家库菜单与“一口清、可比公司维护”等处于原有侧边栏同级，不新增内层侧栏。
- PC 与移动端各自使用本地演示数据，尚未接入统一后台，不自动同步。
- 短信、审批角色、文件附件、签署和费用均有演示边界，不代表真实服务已接通。

当前版本重点是让用户可以看到并操作各个业务环节，不是已经投产的端到端业务系统。

## 2. 用户角色与职责

### “7+5初版名单”口径说明

客户流程图中的“7+5初版名单”不是专家类别，也不是固定人数、名额或准入配额，而是当前已经掌握的理想候选人员名单。7和5仅反映现阶段两批已知候选人员的数量表达，后续人数可以增加、减少或调整。

系统统一将其设计为“初始推荐名单／候选专家池”，不设置“7类”“5类”字段，也不围绕7人、5人编写固定校验规则。页面完成后，再将客户提供的实际名单手工导入。

推荐名单建议保留以下字段：名单批次、姓名、单位、职务、手机号、人员来源、推荐部门、推荐人、关联项目、拟服务领域、推荐理由、名单状态、邀请状态、备注。导入后由股权运营部维护，符合条件的候选人员可以继续发送合作邀请，未进入邀请阶段的人员仍保留在推荐名单中。

| 角色 | 使用端 | 主要职责 |
|---|---|---|
| 专家库管理员 | PC | 选择拟邀请人员、发邀请、核对资料、发起入库审批、协调专家 |
| 分管领导 | PC 工作台 | 查看资料、填写意见、处理入库审批 |
| 需求方 | PC | 提出调用需求、维护申请草稿、确认专家、验收成果 |
| 股权运营部调用受理人 | PC 工作台 | 受理调用需求，通过后允许进入匹配，并在需求部门确认人选后锁定排期 |
| 专家 | 小程序 | 确认入库意愿、填写资料、接收任务、签署承诺、提交成果 |
| 财务人员 | PC，后续建设 | 核对费用、办理结算、登记支付结果 |

需求方负责描述问题和验收结果；专家负责提供专业意见，不验收自己的成果。管理员核对入库资料，不代替分管领导作出审批结论。当前页面角色切换仅用于演示，不是真实账号鉴权。

## 3. 专家入库流程

```text
需求部门推荐人员，股权运营部维护初始推荐名单
  → 发送正式合作邀请函、记录短信通知
  → 专家在小程序查看邀请
      ├─ 拒绝：填写原因，邀请结束
      └─ 同意：开放资料填报
                  → 填写并正式提交完整资料
                  → 需求部门填写正式入库申请表
                  → 系统展示三重校验，股权运营部逐项人工确认并核对
                      ├─ 退回：专家补充资料
                      └─ 符合条件：工作台发起入库审批
                                      → 分管领导办理
                                          ├─ 退回：重新处理申请
                                          └─ 通过：待签发聘书
                                                      → 公司与专家签订3年聘书
                                                      → 经办人登记后正式入库
```

### 3.1 必须区分的三个动作

| 动作 | 含义 | 是否进入领导审批 |
|---|---|---|
| 发送邀请 | 询问专家是否愿意加入 | 否 |
| 同意并提交资料 | 专家表达意愿、提供完整审核依据 | 尚未审批 |
| 发起入库审批 | 管理员将符合条件的申请提交工作台流程 | 是 |

只有专家明确同意、资料完整且正式提交后，管理员才能发起分管领导入库审批。保存草稿不等于提交，同意邀请不等于正式入库。

### 3.2 各环节产物

- 推荐名单：批次、候选人、来源、推荐部门、推荐人、关联项目、领域、理由和状态。
- 发送邀请：正式合作邀请函编号、模板、有效期、邀请记录和短信通知记录。
- 专家确认：同意或拒绝结果；拒绝时保留原因。
- 填报提交：教育经历、工作经历、专业能力、资质成果、服务意愿和声明。
- 需求部门申请：正式《专家入库申请表》及负责人意见。
- 管理员核对：三重校验结果、逐项人工确认、核对结果或退回意见。
- 发起审批：独立流程编号和审批轨迹。
- 领导办理：分管领导线上审批意见、通过或退回结果。
- 正式入库：记录分管领导审批结果、意见、时间和正式入库状态。

分管领导审批通过后进入“待签发聘书”；完成公司与专家双方签订并登记3年聘期后正式入库。审批退回时保留意见，由发起人修改后重新提交。

## 4. 专家调用流程

```text
PC 需求方填写调用申请
  ├─ 保存草稿 → 后续继续编辑
  └─ 提交调用申请
          → 股权运营部受理
              ├─ 退回 → 返回草稿修改
              └─ 通过 → 匹配中
                          → 人工检索、选择专家
                          → 确认人选并生成邀约
                          → 专家在小程序确认
                              ├─ 拒绝或申请改期
                              └─ 接受、申报利益关系、签署承诺
                                          → 提供服务
                                          → 保存成果草稿、正式提交
                                          → PC 需求方验收
                                              ├─ 退回补充
                                              └─ 通过 → 待评价
                                                          → 后续费用结算、项目回溯
```

业务设计上这些环节关联同一调用任务。当前两端独立演示，新建任务和状态变化不会自动传到另一端；预置任务用于分别展示不同阶段。

## 5. PC 页面功能

### 5.1 工作台

路径：`/djghome`。专家业务不得影响 `/gzthome` 的页面及逻辑；审批演示区仅在 `/djghome` 按需加载，入库页面也只链接到 `/djghome`。
    
#### 专家人才库入口

通过“专家人才库”任务入口进入看板，专家库作为现有工作台的一项业务，不另建独立后台。

#### 专家入库审批任务

展示流程编号、专家姓名、当前环节和操作入口，由分管领导办理待审批记录：

1. 查看专家资料和处理轨迹。
2. 填写审批意见。
3. 选择通过或退回。
4. 结果保存到入库记录。

通过后进入“待签发聘书”，聘书签订完成后正式入库；退回保留意见，由发起人修改并重新提交。

#### 专家调用申请受理

展示已提交的调用需求，由股权运营部查看项目、部门、背景、核心问题、领域、时间、成果、截止日期、预算、材料说明和权限并作出受理决定。

- 通过：进入“匹配中”。
- 退回：返回“草稿”，需求方继续编辑。

当前为本地受理演示，没有连接真实工作流、身份和权限服务。

### 5.2 专家库看板

路径：`/expertTalentPool`。

目的：了解资源情况、找到待办和风险方向，不在此填写详细业务表单。

展示内容包括：在库专家、当前可用专家、本月调用、综合评分、我的待办、领域覆盖、紧缺领域和业务动态。

典型用途：管理员查看入库事项，需求方寻找验收事项，管理人员了解专家资源结构。

当前仍以示例统计为主，新发邀请或新建调用不一定更新看板数字，尚未根据实际登录角色生成待办。

### 5.3 专家人才库

路径：`/expertTalentList`。

目的：查询专家及其长期档案，判断专业能力和可用性。它管理“人”，入库管理则管理“申请过程”。

#### 查询列表

- 按姓名、单位、编号、关键词搜索。
- 按主领域和使用状态筛选。
- 查看姓名、编号、单位、职务、领域标签、等级、状态、项目数、评分和可服务时间。

#### 专家档案抽屉

点击姓名或查看档案后打开：

| 页签 | 功能 |
|---|---|
| 基本档案 | 查看编号、等级、类别、领域、聘期和服务意愿 |
| 调用记录 | 查看历史项目、角色、状态和评分 |
| 合规与轨迹 | 查看复核、标签变更、入库等历史示例 |

当前部分档案内容仍是示例。导出及部分旧快捷按钮尚未全面接入新流程；邀请请从入库管理办理，调用请从调用管理发起。

### 5.4 入库管理

路径：`/expertTalentApplications`。

目的：管理邀请、资料核对与入库审批的发起。

#### 发起邀请 Modal

1. 点击“发起邀请”。
2. 搜索并选择拟邀请人员 Demo 数据。
3. 查看人员姓名、手机号、单位、来源。
4. 填写拟服务领域、邀请理由。
5. 查看短信预览，确认发送。

发送后新增待确认邀请及模拟短信记录，不触发领导审批。已有有效邀请的人员受到重复邀请限制。

短信示例：您收到专家入库邀请，请进入小程序，在个人中心—入库邀请查看并确认意向。

#### 邀请和短信记录

用于查看邀请对象、当前状态、邀请内容和模拟发送情况。短信只是提醒，不能据此认定专家已同意。当前没有调用真实短信服务商。

#### 资料核对

对已同意并正式提交完整资料的专家，查看教育经历、工作经历、专业能力、资质成果、服务意愿、声明及历史记录。

- 有问题：退回补充。
- 符合条件：记录核对结果，发起入库审批。
- 刚发邀请、未同意或未完整提交：不能发起审批。

#### 发起入库审批

生成独立演示流程编号，进入工作台审批区域。入库管理负责准备和发起，审批人到工作台办理。

页面预置“完整资料待核对”记录，方便演示后半段；该记录不是小程序提交后自动同步得到的。

### 5.5 调用管理

路径：`/expertTalentTasks`。

目的：管理一项专家咨询需求，从申请、审批、选人到成果验收。

#### 调用申请表单

| 字段 | 用途 |
|---|---|
| 项目名称 | 标识咨询事项 |
| 需求部门 | 明确需求来源 |
| 项目背景 | 说明为什么需要专家 |
| 核心问题 | 明确希望专家回答什么 |
| 所需领域 | 提供匹配依据 |
| 服务时间 | 明确计划安排 |
| 交付截止日期 | 明确成果期限 |
| 交付要求／期望成果 | 约定报告、意见、风险清单等 |
| 材料说明 | 描述拟提供的项目资料，当前不上传真实文件 |
| 材料访问权限 | 描述查看范围，当前不代表真实鉴权 |
| 预算上限 | 明确金额上限，0表示无偿 |

保存草稿允许后续继续填写；提交调用申请校验必填字段和预算，进入“调用受理中”，由股权运营部办理，不直接派给专家。

#### 任务列表

展示项目、部门、领域、专家和状态。草稿提供“继续编辑草稿”，其他记录进入任务详情。

#### 任务详情：需求与轨迹

展示完整申请及处理历史：保存草稿、发起审批、审批通过或退回、人工确认专家、验收等。记录演示操作者、时间和说明。

#### 任务详情：专家匹配

仅“匹配中”可确认人选：

1. 按姓名、单位、领域或标签查询候选专家。
2. 查看领域、可用状态、风险、匹配参考信息和服务时间。
3. 单选一名专家。
4. 填写人工匹配理由。
5. 确认已核对项目冲突、资质聘期、排期和任务容量。
6. 确认人选并生成模拟邀约。

非可用状态或风险不正常的专家不可选。其他条件由演示经办人核对，不宣称已接入自动关联或资质核验。确认后记录人选和理由，进入“待专家确认”，不会自动发送到小程序。

#### 任务详情：成果与验收

展示正式成果的版本、提交时间、正文和模拟附件。专家尚未提交的私人草稿不在这里验收。

| 操作 | 前置条件 | 结果 |
|---|---|---|
| 验收通过 | 待验收、有正式成果、填写验收意见 | 记录对应版本，进入待评价 |
| 退回补充 | 待验收、有正式成果、填写原因和未来补充期限 | 进入待补充，保留记录 |

PC 不直接改写专家成果。当前依靠预置正式成果演示验收，移动端新提交内容及 PC 退回意见不会跨端同步。

### 5.6 评价与回溯

路径：`/expertTalentEvaluation`。

目的：分别评价服务质量与专业判断结果。

- 履约评价：交付性50%、响应效率30%、服务态度20%。
- 项目回溯：将历史观点与实际结果对比，记录命中、部分命中、偏离、证伪。

两者独立保留：服务认真不代表预测一定正确，不能相互覆盖。

当前展示统计、评价记录及分布。完整填报、观点回溯、异议办理及验收后自动创建评价任务尚未完成。

### 5.7 运营管理

路径：`/expertTalentOperations`。

目的：维护各页面共用的标签分类、准入等级、匹配策略、费用标准、表单模板、通知和审计规则。

当前主要可操作区域是匹配权重输入和合计展示。其他分类多为展示；保存未形成完整版本管理，费用标准入口不等于费用结算已经实现。

## 6. 小程序页面功能

### 6.1 个人中心

作为个人业务总入口，提供入库邀请、消息，以及按身份展示的专家工作区、档案、任务、费用、可服务时间。

本轮新增可直接发现的“入库邀请”，不必先进入工作区寻找。普通服务申请导航已移除，旧申请路由不再开放提交。

### 6.2 入库邀请

入口：个人中心 → 入库邀请；或产业协同 → 专家人才 → 入库邀请。

展示邀请编号、被邀请人、脱敏手机号、领域、说明、状态及短信演示文案。

| 状态 | 可操作内容 |
|---|---|
| 待专家确认 | 同意并完善资料、拒绝邀请 |
| 待完善资料 | 继续填写教育经历、专业能力等 |
| 已拒绝 | 查看拒绝原因 |
| 已提交 | 查看入库进度 |

拒绝需填写原因；同意后开放入库表单。默认预置一条独立邀请，不来自 PC 实时发送。

### 6.3 六步入库资料

| 步骤 | 内容 |
|---|---|
| 身份与基本信息 | 姓名、性别、出生日期、证件、邮箱、单位、职务职称 |
| 教育与工作经历 | 学历院校专业、教育时间、工作经历、从业年限 |
| 专业能力 | 类别、领域、关键词、代表项目、可承担角色 |
| 资质与成果 | 证书及有效期、研究成果、获奖、模拟附件 |
| 服务意愿与声明 | 城市地区、形式时间、出差意愿、相关授权声明 |
| 确认提交 | 汇总核对并正式提交 |

支持分步填写和本地草稿保存。未同意不能提交；正式提交检查必要资料与声明，之后待资料核对，不自动入库。预填资料是演示内容，不是经过核验的真实履历。

### 6.4 入库进度

展示手续节点及处理说明，让专家知道资料提交后由管理员核对，再从 PC 发起分管领导审批。当前不自动读取 PC 结果，不自动转正式入库。

### 6.5 专家工作区

展示个人身份状态、服务概览、待办、近期安排、消息，以及档案、费用、排期快捷入口和入库邀请入口。不展示其他专家或公司内部运营数据。

### 6.6 我的任务

按待处理、进行中、已完成等查看本人任务。任务卡显示名称、脱敏项目、状态、形式、时间及详情入口。

状态决定动作：待确认可接受拒绝或改期；待签署需完成承诺；待交付可填写成果；退回补充可修改；待验收等待需求方；已完成查看历史。

### 6.7 任务详情

| 页签 | 内容 |
|---|---|
| 概览 | 项目摘要、时间形式、截止日期、诉求、费用说明 |
| 材料 | 当前任务允许查看的材料演示 |
| 交付 | 正式版本和填写成果入口 |
| 记录 | 邀约、承诺、改期、交付等轨迹 |

接受前、承诺未完成或利益关系待复核时，不直接开放进一步材料。

### 6.8 利益关系与承诺

接受服务邀约后申报关系并完成承诺。不存在利益关系则进入排期；存在或可能存在时填写说明，进入合规复核。当前不连接真实电子签署。

### 6.9 咨询记录与成果交付

入口：我的任务 → 任务详情 → 交付。

填写咨询目的、观点、依据、风险和建议，添加模拟附件。

- 保存草稿：本人后续继续编辑。
- 正式提交：保留版本，进入待验收，不直接进入待评价。
- 退回补充任务：在已有基础上继续编辑、重新提交并保留旧版本。

| 草稿类型 | 编辑人 | 位置 |
|---|---|---|
| 调用申请草稿 | PC需求方 | 调用管理 → 继续编辑草稿 |
| 专家成果草稿 | 小程序专家 | 任务详情 → 交付 |

### 6.10 我的档案

查看个人专业资料并提出变更。重要信息业务上应审核后生效，不应直接覆盖正式档案；当前为演示。

### 6.11 可服务时间

维护常规安排、不可用日期和暂停服务状态。变更时间不应自动取消已确认任务，冲突需协调处理。

### 6.12 我的费用

查看本人任务费用状态、金额和规则说明，不开放其他专家费用及内部预算。当前无真实付款接口。

### 6.13 消息中心

包含入库邀请通知、任务、审核、费用等演示消息。点击入库邀请通知直接进入邀请详情。当前不是微信真实推送。

## 7. 推荐演示顺序

### 场景A：专家收到邀请后填资料

1. 打开移动端 v4，进入个人中心。
2. 点击入库邀请，查看说明。
3. 同意并完善资料。
4. 填写六步表单，保存或提交。
5. 查看入库进度。

### 场景B：管理员邀请及领导审批

1. PC入库管理发起邀请，选择可邀请人员。
2. 填写领域理由、预览短信并发送。
3. 查看邀请和模拟短信记录。
4. 打开预置的完整资料待核对记录。
5. 核对后发起入库审批。
6. 在工作台“专家入库审批”任务填写分管领导意见并处理。
7. 审批通过后返回入库管理登记已签署聘书、编号、签订日期、3年聘期及附件，完成后查看“已正式入库”结果；审批退回则补充后重新提交。

### 场景C：调用、匹配及验收

1. PC创建调用申请，保存草稿。
2. 从列表重新编辑，提交审批。
3. 工作台审批通过后进入匹配。
4. 在任务详情选择专家、填写理由并生成模拟邀约。
5. 使用移动端预置任务演示成果草稿及提交。
6. 使用PC预置待验收任务演示通过或退回。

第5步与第6步不是同一任务实时跨端流转，而是分别演示专家交付与需求方验收。
