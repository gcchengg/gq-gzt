# 专家人才库产品需求文档（PRD·领导演示版）

> 文档版本：V1.0  
> 更新日期：2026年9月8日  
> 适用范围：专家人才库 PC 工作台、专家微信小程序  
> 文档用途：方案汇报、领导演示、产品评审及后续研发对接  
> 当前阶段：高保真交互原型，部分流程使用本地演示数据

## 1. 项目概述

### 1.1 建设背景

公司在产业研究、投资研判、技术尽调、公司治理、财务法务及经营管理等业务中，需要持续调用内部和外部专家。当前专家资源、推荐过程、入库资料、聘任关系、调用过程和咨询成果缺少统一载体，容易出现以下问题：

- 专家名单分散，专业方向、履约记录和可服务状态难以统一查询。
- 专家入库过程缺少标准化邀请、资料核对、领导审批和聘书签署链路。
- 调用需求、专家匹配、排期邀约、声明签署、咨询记录和验收评价未形成闭环。
- 专家费用标准、业务表单和关键操作缺少统一规则管理。
- 专家参与项目时的独立性和利害关系声明缺少在线签署和留痕机制。

因此，本项目建设“PC工作台＋专家微信小程序”双端协同的专家人才库，将专家从候选推荐、入库聘任到调用履约、评价回溯的全过程纳入统一管理。

### 1.2 建设目标

1. 建立统一、可查询、可维护的专家档案库。
2. 建立“先邀请、后填报、再审核审批、签署聘书、正式入库”的标准入库流程。
3. 建立“需求申请、运营受理、人工匹配、排期邀约、声明签署、咨询记录、验收评价”的调用闭环。
4. 用 E签宝承载专家聘书和利害关系承诺声明的电子签署。
5. 将服务质量评价和专业观点后续回溯分别记录，持续优化专家画像。
6. 在不改变现有 `/gzthome` 逻辑的前提下，将专家业务融入现有 PC 工作台体系。

### 1.3 本期建设边界

本期包含：

- PC端专家库看板、专家人才库、入库管理、调用管理、评价与回溯、运营管理。
- `/djghome` 中专家入库审批与专家调用受理任务。
- 专家微信小程序中的入库邀请、资料填报、聘书签署、调用邀约、声明签署、咨询记录、档案与任务查看。
- PDF样式预览、浏览器打印及另存为PDF的原型能力。
- 本地演示数据、状态流转和关键操作留痕。

本期不包含或尚未真实接通：

- 真实组织、账号、岗位和数据权限。
- 真实短信平台、微信订阅消息和统一消息中心。
- E签宝真实实名认证、签署任务创建、回调验签和签署文件归档。
- PC与小程序统一后端数据同步。
- 真实附件上传、在线预览、水印、下载控制和对象存储。
- 财务付款、税务处理及真实结算接口。

### 1.4 强制隔离要求

`/gzthome` 路径下任何现有页面、任务逻辑、默认选中项和数据初始化均不得受到专家人才库影响。专家业务仅在 `/djghome` 和 `/expertTalent*` 系列路由中加载。

## 2. 核心设计原则

### 2.1 单一业务入口

- 专家调用需求统一由需求方从 PC 发起。
- 小程序不提供普通用户申请专家服务的入口。
- 小程序只服务受邀专家，用于入库、签署、接收任务和提交咨询记录。

### 2.2 人工决策优先

系统可以展示专家推荐排序、匹配依据和回避风险，但不能自动决定最终人选。需求部门必须人工选择并填写确认理由，股权运营部负责协调并锁定排期。

### 2.3 状态驱动操作

每个状态只开放当前环节需要的操作。例如：

- 未完成资料核对，不允许发起入库审批。
- 未正式聘用，不允许发起专家调用。
- 未完成 E签宝声明签署，不允许填写咨询记录。
- 进入待评价后，申请、匹配、排期、声明和咨询记录全部只读，只允许填写评价。

### 2.4 关键动作可追溯

邀请、提交、退回、审批、签署、选人、锁定排期、提交咨询记录、验收和评价均记录操作人、时间、结果和意见。

### 2.5 业务原件化

《专家调用申请表》《咨询记录》《利害关系承诺声明》和聘书不是页面说明材料，而是业务流程中的正式产物。系统需支持结构化填报、PDF预览、打印和归档。

## 3. 角色与职责

| 角色 | 使用端 | 主要职责 | 不承担的职责 |
|---|---|---|---|
| 需求部门推荐人 | PC | 推荐候选专家，补充来源、领域和推荐理由 | 不代表专家本人确认入库 |
| 专家库管理员/股权运营部 | PC | 维护名单、发送邀请、核对资料、发起审批、发送聘书、维护规则 | 不代替领导审批，不代替专家签署 |
| 分管领导 | PC工作台 | 审批首次入库和续聘申请，填写审批意见 | 不负责资料录入和日常匹配 |
| 专家调用需求方 | PC | 填写调用申请、确认专家、验收咨询记录、评价专家 | 不在小程序重复发起需求 |
| 调用受理人/股权运营部 | PC工作台 | 受理调用申请、协调专家、锁定排期并生成邀约 | 不代替需求部门验收成果 |
| 受邀专家 | 微信小程序 | 确认入库意愿、填写档案、签聘书、接收邀约、签声明、填写咨询记录 | 不验收或评价自己的成果 |
| 财务人员 | PC后续能力 | 根据标准核对咨询费和差旅费、处理支付 | 不改变专家履约评价 |
| 系统管理员 | PC | 维护标签、准入规则、费用标准、模板、通知和审计配置 | 不作业务审批结论 |

### 3.1 “7＋5名单”口径

“7”和“5”只表示当前已掌握的两批理想候选人员名单，不代表专家类别、固定人数、名额或配额。系统统一设计为“初始推荐名单/候选专家池”，不设置7类、5类字段，也不设置固定人数校验。页面完成后由业务人员手工导入实际名单。

## 5. 专家入库业务流程

### 5.1 主流程

```text
需求部门推荐候选人员
  → 股权运营部维护初始推荐名单
  → 选择人员并生成《专家合作邀请函》
  → 短信通知专家到小程序查看
  → 专家查看邀请
      ├─ 拒绝：填写原因，流程结束
      └─ 同意：开放六步资料填报
                  → 专家保存草稿
                  → 专家完整提交资料
                  → 需求部门填写《专家入库申请表》
                  → 股权运营部查看专家全部资料
                  → 完整性、准入、关联合规三重校验
                  → 经办人逐项人工确认
                      ├─ 退回补充：专家修改后重新提交
                      └─ 核对完成：发起工作台审批
                                      → 总监审批
                                      → 分管领导审批
                                          ├─ 退回：发起人修改后重提
                                          └─ 通过：待签发聘书
                                                      → 公司发送3年期聘书
                                                      → 专家在小程序进入E签宝签署
                                                      → E签宝签署成功回调
                                                      → 正式入库并生成专家档案
```

### 5.2 关键业务规则

1. 发送邀请不等于提交入库审批。
2. 专家同意邀请不等于正式入库。
3. 只有专家同意并完整提交资料后，才允许资料核对。
4. 只有入库申请表完整、三重校验逐项人工确认后，才能发起审批。
5. 审批在工作台中办理，审批节点为总监审批、分管领导审批。
6. 不设置总办会线上流程，不登记线下总办会。
7. 分管领导通过后进入“待签发聘书”，不能直接正式入库。
8. 聘书固定聘期3年，期满可续聘。
9. 专家在小程序通过 E签宝签署聘书，签署回调成功后才正式入库。
10. 普通专家年龄不超过65周岁，高层次专家不超过70周岁。
11. 聘期或年龄上限临近时触发预警；达到年龄上限或不满足履约条件时可以主动解聘。
12. 续聘也需要分管领导审批，审批通过后发送续聘聘书并再次签署。

### 5.3 入库状态定义

| 状态 | 含义 | 允许操作 |
|---|---|---|
| 待邀请 | 已进入推荐名单，尚未发送邀请 | 发起邀请 |
| 待专家确认 | 邀请函已生成，短信已提醒 | 专家同意或拒绝 |
| 待完善资料 | 专家已同意，尚未完整提交 | 保存草稿、继续填写 |
| 待资料核对 | 专家已正式提交资料 | 查看全部资料、退回、完成核对 |
| 核对完成 | 资料和入库申请符合提交条件 | 发起工作台审批 |
| 领导审批中 | 总监或分管领导正在审批 | 查看审批详情，不修改已提交资料 |
| 审批退回 | 审批人要求补充或调整 | 修改后重新提交 |
| 待签发聘书 | 分管领导审批通过 | 配置并发送聘书 |
| 待专家签署 | 聘书已发送到小程序和E签宝 | 查看签署状态、催办 |
| 已正式入库 | E签宝签署回调成功 | 查询档案、允许发起调用 |
| 待续聘 | 聘期即将届满 | 发起续聘审批 |
| 续聘审批中 | 续聘正在审批 | 查看审批详情 |
| 待签发续聘聘书 | 续聘审批通过 | 发送续聘聘书 |
| 限制调用 | 存在合规、资质或其他风险 | 不允许新增调用 |
| 已解聘 | 聘任关系结束 | 只读查看历史记录 |

## 6. 专家调用业务流程

### 6.1 主流程

```text
需求方从PC填写《专家调用申请表》
  ├─ 保存草稿：后续继续编辑
  └─ 提交：调用受理中
          → 股权运营部受理
              ├─ 退回：返回需求方修改
              └─ 受理：进入推荐匹配
                      → 系统展示候选排序和推荐依据
                      → 需求方人工确认或调整专家并填写理由
                      → 股权运营部协调服务时间
                      → 锁定排期并生成专家邀约
                      → 同时生成《利害关系承诺声明》E签宝签署单
                      → 专家在小程序处理
                          ├─ 拒绝邀约/申请改期：返回协调
                          ├─ 申报存在利益关系：进入合规复核
                          └─ 无利益冲突：进入E签宝签署
                                  ├─ 拒签/失效：停止履约或重新发起
                                  └─ 签署成功：解锁材料和《咨询记录》
                                          → 开展咨询
                                          → 保存咨询记录草稿
                                          → 正式提交咨询记录
                                          → 需求方验收
                                              ├─ 退回补充：专家修改重提
                                              └─ 验收通过：待评价
                                                      → 需求方评价专家
                                                      → 已完成
                                                      → 后续费用结算和观点回溯
```

### 6.2 调用状态定义

| 状态 | 页面表现 | 可操作角色和动作 |
|---|---|---|
| 草稿 | 任务列表显示“继续编辑草稿” | 需求方编辑、PDF预览、提交 |
| 调用受理中 | 候选表只读 | 股权运营部受理或退回 |
| 匹配中 | 候选表可选 | 需求方选择专家、填写理由并确认 |
| 待运营排期 | 已确认专家 | 可重新确认专家；运营部填写排期和协调说明 |
| 待专家签署声明 | 显示E签宝签署单 | 专家在小程序签署；PC查看状态 |
| 声明拒签 | 任务停止履约 | 查看拒签结果，后续重新协调 |
| 声明失效 | 签署任务超过有效期 | 查看失效结果，后续重新发起 |
| 履约中 | 声明已签署 | 填写并保存咨询记录 |
| 待验收 | 正式咨询记录已提交 | 需求方验收通过或退回补充 |
| 待补充 | 保留退回原因和期限 | 专家补充咨询记录并再次提交 |
| 待评价 | 其他业务信息全部只读 | 仅需求方填写履约评价 |
| 已完成 | 展示咨询记录、验收及评价结果 | 只读查看、后续回溯与结算 |

### 6.3 专家选择规则

- 只有“匹配中”和“待运营排期”允许选择或重新调整专家。
- 点击单选框或候选专家所在行均可选中。
- 专家必须已正式聘用、聘期有效且未处于限制调用或已解聘状态。
- 系统展示领域匹配、标签、历史项目、可服务时间和回避校验。
- 系统推荐仅供参考，最终选择必须由需求部门人工确认。
- 若人工选择并非系统首选，需保留调整标识及理由。
- 已锁定排期后，候选表转为只读。

## 7. PC端页面需求

## 7.1 `/djghome` 原工作台

### 页面定位

专家人才库不新建独立审批中心，入库审批和调用受理融入现有任务列表，与原有任务处于同一层级。

### 专家入库审批任务

- 显示申请编号、专家姓名、申请部门、当前审批节点和发起时间。
- 点击进入审批详情，查看专家完整资料、入库申请、资料核对结果和审批轨迹。
- 审批轨迹展示申请人、总监、分管领导；不展示抄送节点。
- 审批人填写意见并选择通过或退回。
- 分管领导通过后，入库记录进入“待签发聘书”。

### 专家调用受理任务

- 显示调用申请项目、需求部门、领域、期望时间和预算。
- 股权运营部查看完整调用申请并受理。
- 受理通过后任务进入“匹配中”；退回后需求方继续修改草稿。

## 7.2 `/expertTalentPool` 专家库看板

### 页面定位

为管理层和运营人员提供专家资源概况、业务待办和风险提示，不承担详细表单办理。

### 展示内容

- 在库专家数量、当前可用数量、本月调用数量和综合评分。
- 我的待办：入库审核、候选确认、交付验收和专家评价。
- 领域覆盖情况及紧缺领域。
- 最近入库、调用、签署和验收动态。

### 说明

当前看板数字主要为演示数据，正式建设需改为实时统计并按登录用户权限展示。

## 7.3 `/expertTalentList` 专家人才库

### 页面定位

管理已经完成正式入库的专家及其长期档案，回答“有哪些专家、能力如何、当前能否调用”。

### 列表功能

- 按姓名、单位、专家编号和标签搜索。
- 按主领域和状态筛选。
- 展示专家姓名、编号、单位、职务、领域、等级、状态、历史项目数、评分和可服务时间。
- 各类状态均配置多条演示数据，包括可用、忙碌、待续聘、续聘审批中、待签发续聘聘书、限制调用和已解聘。

### 专家档案抽屉

| 页签 | 内容 |
|---|---|
| 基本档案 | 编号、类别、等级、领域、出生日期、服务意愿、历史项目和专业画像 |
| 聘期管理 | 年龄上限、当前聘期、续聘审批、聘书记录、主动解聘 |
| 调用记录 | 历史调用项目、承担角色、任务状态和评分 |
| 合规与轨迹 | 入库、续聘、限制调用、解聘等操作历史 |

### 发起调用

- 仅正式聘用且聘期有效的专家允许点击。
- 限制调用、已解聘或聘期已结束时按钮禁用并显示原因。
- 点击后跳转 `/expertTalentTasks`，自动打开《专家调用申请表》并预选当前专家。

## 7.4 `/expertTalentApplications` 入库管理

### 页签一：初始推荐名单

- 新增候选人员。
- 搜索和批量选择。
- CSV文本导入演示。
- 查看名单批次、姓名、单位、职务、手机号、来源、推荐部门、推荐人、关联项目、领域、推荐理由和状态。
- 将候选人员转为入库邀请。

### 页签二：入库办理

- 展示邀请函编号、模板、有效期、邀请状态和资料状态。
- “发起邀请”Modal提供可选择人员的演示数据。
- 发送邀请时生成正式邀请记录，并生成短信提醒记录。
- 短信只提示“请到小程序查看”，不承载正式邀请内容。

### 办理详情

根据状态只显示当前可执行按钮，不同时展示所有办理动作：

| 状态 | 显示操作 |
|---|---|
| 待资料核对 | 退回补充、完成资料与申请核对 |
| 核对完成 | 发起领导审批 |
| 领导审批中 | 查看审批详情 |
| 审批退回 | 修改补充、重新完成核对 |
| 待签发聘书 | 发送聘书 |
| 待专家签署 | 查看签署状态 |
| 已正式入库 | 查看正式档案 |

所有会改变业务状态的按钮均需二次确认。

### 资料核对内容

发起人必须能看到专家在小程序提交的全部信息：

- 身份与基本信息。
- 教育与工作经历。
- 专业能力、领域和技术关键词。
- 代表项目、承担职责和可承担角色。
- 证书、资质、成果和附件。
- 服务地区、服务形式、可服务时间和出差意愿。
- 诚信、保密、利益关联和个人信息授权声明。
- 需求部门填写的《专家入库申请表》。
- 完整性、准入和关联合规三重校验。

### 聘书发送

- 公司填写聘书编号、3年聘期、签署截止日期和聘书文件。
- 点击发送后，专家在小程序收到聘书待签通知。
- 专家跳转 E签宝签署。
- 签署回调成功后正式入库。

## 7.5 `/expertTalentTasks` 调用管理

### 任务列表

表格展示项目、需求部门、领域、专家、状态和操作，并提供以下筛选条件：

- 项目名称、工单号或专家关键词。
- 任务状态。
- 需求部门。
- 所需领域。
- 已选专家。
- 重置筛选及结果数量。

### 《专家调用申请表》

| 分组 | 字段 |
|---|---|
| 基础标识 | 工单编号、填报日期 |
| 需求方 | 需求发起部门、申请人、联系电话/邮箱 |
| 项目基础 | 项目名称、项目投资额、项目背景、核心诉求 |
| 专家服务 | 所需领域、意向专家、服务形式、预计服务时间段 |
| 交付验收 | 最终交付截止时间、交付与验收要求 |
| 材料权限 | 材料说明、材料访问权限 |
| 费用测算 | 专家来源与职级、半天标准、预计时长、预计总费用、预算上限 |

操作包括保存草稿、提交受理、PDF样式预览和打印/另存为PDF。

### 任务详情：需求与轨迹

- 只读展示完整申请信息、费用测算和当前状态。
- 展示每次保存、受理、选人、排期、签署、提交、验收和评价记录。
- “调用受理中”时，为运营人员提供受理入口。

### 任务详情：推荐匹配与排期

- 展示系统推荐列表、参考分、推荐依据和回避校验。
- 支持关键词查询，点击单选框或整行选择专家。
- 不可调用专家置灰，并提示具体原因。
- 需求部门填写确认或调整理由，并勾选人工核对确认。
- 股权运营部填写最终服务时间和协调说明。
- 点击“锁定排期并生成邀约”后，生成专家邀约及 E签宝声明签署任务。
- 展示签署单号、创建时间、签署时间、利益关系申报和签署状态。
- 原型提供签署成功、拒签和失效模拟回调。

### 任务详情：成果与验收

未签署声明时：

- 显示“咨询记录尚未解锁”。
- 禁止编辑或提交咨询记录。

声明签署成功后：

- 显示签署时间和解锁状态。
- 开放《咨询记录》填写。

《咨询记录》字段如下：

| 分组 | 字段 |
|---|---|
| 基础信息 | 项目名称、项目等级、咨询日期、咨询人、咨询方式、咨询时长、专家姓名、所属领域 |
| 咨询目的 | 咨询核心目的 |
| 内容记录 | 多条咨询问题及对应专家答复 |
| 核心观点 | 事实类、判断类、逻辑类观点 |
| 风险建议 | 核心风险点、后续行动建议 |
| 成果附件 | 咨询报告或其他成果附件 |
| 归档信息 | 归档编号、归档日期、需求部门审核和备注 |

支持保存草稿、正式提交、PDF预览和打印。正式提交后进入“待验收”。

### 验收

- 需求部门填写验收意见。
- 验收通过后进入“待评价”。
- 退回补充必须填写原因和未来补充期限，任务进入“待补充”。
- PC不能直接修改专家已提交的正式咨询记录。

### 待评价只读控制

当状态为“待评价”时：

- 调用申请不可编辑。
- 推荐匹配和人选不可调整。
- 排期、协调说明和声明不可编辑。
- 咨询记录字段不可编辑。
- 不显示保存咨询记录和正式提交按钮。
- 保留咨询记录 PDF预览和打印。
- 唯一允许编辑的是“本次专家调用履约评价”。

### 履约评价表

| 指标 | 最高分 | 说明 |
|---|---:|---|
| 交付质量 | 50 | 内容完整性、专业性、问题覆盖和可用性 |
| 响应效率 | 30 | 响应及时性、排期配合和补充反馈效率 |
| 服务态度 | 20 | 沟通配合、责任意识和服务体验 |

需求方还需选择评价标签、填写评价说明，并可选择向专家隐藏评价人姓名。系统自动计算总分：90分及以上为优秀，75至89分为良好，75分以下为一般。提交前二次确认，提交后任务变为“已完成”，评价不可重复编辑。

## 7.6 `/expertTalentEvaluation` 评价与回溯

### 页面定位

统一查看专家履约评价，并在项目结果可验证后对历史专业观点进行回溯。

### 履约评价

- 自动汇总调用管理中已经提交的评价。
- 展示项目、专家、三项得分、评价结果、评价日期和评价说明。
- 评价结果进入专家长期档案和后续推荐参考。

### 观点回溯

- 与履约评分分开管理。
- 可记录“命中、部分命中、偏离、证伪、待回溯”等结果。
- 服务态度良好不等于观点一定正确，观点未命中也不能直接覆盖履约评价。

当前观点回溯主要为展示数据，正式填报、证据附件和异议流程属于后续能力。

## 7.7 `/expertTalentOperations` 运营管理

### 页面定位

集中维护专家库各业务页面共用的规则和模板。该页面不是 PPT 明确要求的独立模块，而是为了避免规则散落和硬编码而形成的管理能力。

### 配置模块

1. **标签与分类**：维护专家类别和主领域，支持直接新增标签。
2. **准入与等级**：维护普通/高层次专家年龄上限、聘期、最低从业年限和预警天数。
3. **匹配策略**：维护专业标签、项目经验、履约质量、观点回溯、可用时间和调用均衡度权重，合计必须为100%。
4. **费用标准**：展示外聘和内部专家费用标准及计费规则。
5. **表单与模板**：维护邀请函、聘书、调用申请表、声明、咨询记录和评价表，支持预览和模拟编辑。
6. **通知与审计**：维护短信、小程序消息、工作台待办和到期提醒开关，查看关键操作日志。

当前配置保存在浏览器本地，用于演示；正式系统应支持权限控制、版本发布、生效时间、历史版本和操作审计。

## 8.4 聘书 E签宝签署

- 分管领导审批通过后，专家收到聘书待签通知。
- 查看聘书编号、3年聘期、签署截止日期、文件名称和签署平台。
- 点击“前往E签宝签署”。
- 完成实名认证、签署意愿确认和电子签名。
- E签宝回调成功后，小程序显示已正式入库。

## 8.5 我的任务与调用邀约

- 展示待处理、进行中和已完成任务。
- 专家查看项目名称、服务时间、服务形式、交付截止日期和核心诉求。
- 待确认邀约支持接受、拒绝和申请改期。
- 接受后进入利害关系申报和声明签署。

## 8.6 利害关系承诺声明 E签宝签署

声明包含以下核心内容：

- 专家本人及近亲属与标的公司、主要股东、董事、监事和高级管理人员不存在影响交易公允性的关联关系。
- 未替标的公司承担费用、输送不正当利益或获取商业机会。
- 声明内容真实、准确、完整，并承担相应责任。
- 声明自签署日起至本次交易或咨询服务完成期间持续有效。

操作过程：

1. 专家选择是否存在或可能存在利益关系。
2. 如存在，必须说明关系并进入合规复核，不直接生成签署单。
3. 如不存在，生成 E签宝签署单和声明PDF。
4. 专家跳转 E签宝完成电子签署。
5. 签署成功后开放项目材料和咨询记录。
6. 拒签或签署失效时，不允许开展后续履约。

## 8.7 咨询记录与成果提交

- 只有声明签署成功后才能进入。
- 字段与 PC《咨询记录》一致，包括日期、方式、时长、参与人员、咨询目的、问题与答复、三类核心观点、风险提示和行动建议。
- 支持保存草稿、添加演示附件和正式提交。
- 正式提交后进入待验收，专家不能覆盖历史正式版本。
- PC退回补充后，专家查看退回意见和期限并提交新版本。

## 9. 费用标准与测算规则

### 9.1 外聘专家费用标准

税后，单位：元/人/半天。

| 职称级别 | 标准 |
|---|---:|
| 中国科学院院士或中国工程院院士 | 2500 |
| 高级专家（享受国务院特别津贴或国家级、省部级特殊人才计划） | 2000 |
| 正高级职称/教授 | 1500 |
| 副高级职称/副教授 | 1000 |
| 中级职称 | 800 |
| 其他人员 | 500 |

### 9.2 集团内部专家费用标准

税前，单位：元/人/半天，职级与职称按就高原则执行。

| 职级/职称 | 业余时间 | 工作时间 |
|---|---:|---:|
| 首席科学家 | 2000 | 1500 |
| 专家、总师、正高级职称 | 1500 | 1000 |
| 主任级、副高级职称 | 800 | 500 |
| 主管级、中级职称 | 600 | 400 |
| 其他人员 | 400 | 250 |

### 9.3 时长规则

- 不足2小时，按半天标准折半。
- 2至4小时，按半天计算。
- 超过2天，第1至2天按标准执行，第3天起按标准的50%执行。
- 差旅费参照一汽股权对应等级标准，由一汽股权承担。
- 咨询费和专家差旅费在“管理费用－咨询费”中列支。
- 调用申请中的金额为预计试算，实际支付以财务审批和最终履约为准。

## 11. 权限与只读要求

### 11.1 最小权限原则

- 专家只查看本人邀请、本人档案、本人任务和授权材料。
- 需求部门只查看本部门发起的调用及相应成果。
- 运营部查看专家库运营范围内的入库与调用数据。
- 审批人只在待本人办理节点执行审批。
- 财务只查看结算必需的任务、人员和费用信息。

### 11.2 状态锁定

- 已提交申请在审批/受理期间只读，退回后重新开放。
- 已签署的聘书和声明不可直接覆盖，只能形成新版本或新签署任务。
- 正式提交的咨询记录不可直接修改，退回后形成新版本。
- 待评价时除评价区域外全部只读。
- 已完成和已解聘记录只读保留。

## 13. 异常与边界处理

| 场景 | 系统处理 |
|---|---|
| 重复邀请同一人员 | 已有有效邀请时禁止重复发送 |
| 专家未完整提交资料 | 禁止资料核对完成和发起审批 |
| 三重校验未人工确认 | 禁止发起领导审批 |
| 审批退回 | 保留意见，返回发起人修改后重提 |
| 聘书拒签或失效 | 不正式入库，保留签署状态 |
| 专家聘期无效或限制调用 | 禁用“发起调用”并显示原因 |
| 候选专家忙碌或回避不通过 | 候选项置灰并提示原因 |
| 声明申报存在利益关系 | 转合规复核，暂不开放材料和履约 |
| 声明拒签或失效 | 不开放咨询记录 |
| 未提交正式咨询记录 | 不允许验收 |
| 验收退回未填期限 | 禁止提交退回操作 |
| 待评价尝试修改其他内容 | 所有非评价表单只读 |
| 本地保存失败 | 提示检查浏览器存储，避免误认为已保存 |

## 14. 领导演示建议脚本

### 14.1 演示一：专家从候选名单到正式入库

1. 从 `/djghome` 进入专家人才库。
2. 打开 `/expertTalentApplications`，介绍“初始推荐名单不是固定7＋5人数”。
3. 点击发起邀请，选择演示人员，展示邀请函和短信预览。
4. 切换小程序，打开“个人中心－入库邀请”。
5. 专家同意邀请，展示六步资料填写，重点演示教育经历和专业能力。
6. 回到 PC 办理详情，查看专家提交的全部资料和需求部门入库申请。
7. 完成三重校验，发起领导审批。
8. 到 `/djghome` 展示总监、分管领导审批详情。
9. 审批通过后回到入库管理，展示“待签发聘书”。
10. 发送3年期聘书，在小程序进入 E签宝签署。
11. 模拟签署成功回调，展示“已正式入库”和专家档案。

讲解重点：邀请、审批和正式入库是三个不同节点；领导审批通过后还必须完成聘书签署。

### 14.2 演示二：从专家档案发起调用

1. 打开 `/expertTalentList`，筛选“可用”专家。
2. 点击专家档案，介绍基本档案、聘期、历史调用和合规轨迹。
3. 点击“发起调用”，自动跳转 `/expertTalentTasks` 并预选专家。
4. 填写《专家调用申请表》，展示费用自动试算。
5. 点击 PDF预览和打印，说明该表作为正式业务产物归档。
6. 提交后演示运营受理，进入推荐匹配。

讲解重点：只有正式聘用且聘期有效的专家可以发起调用。

### 14.3 演示三：人工匹配、排期和声明签署

1. 打开“推荐匹配与排期”Tab。
2. 说明系统排序只提供参考，不自动决定人选。
3. 点击候选专家所在行，填写人工确认理由并确认。
4. 股权运营部填写最终服务时间和协调说明。
5. 锁定排期并生成邀约，展示 E签宝声明签署单号。
6. 切换小程序，专家查看声明、申报利益关系并进入 E签宝。
7. 模拟签署成功，回到 PC 展示“声明已签署，咨询记录已解锁”。

讲解重点：声明签署是材料开放和开展咨询的前置条件。

### 14.4 演示四：咨询记录、验收和评价

1. 打开“成果与验收”Tab，选择一条 E签宝已签署的演示任务。
2. 展示完整《咨询记录》，包括问题与答复、事实/判断/逻辑三类观点、风险和行动建议。
3. 展示 PDF预览和打印。
4. 正式提交后由需求方填写验收意见。
5. 验收通过，任务进入“待评价”。
6. 说明待评价时除评价区域外所有内容只读。
7. 填写三项评分、评价标签和评价说明，提交后任务完成。
8. 打开 `/expertTalentEvaluation`，展示评价已经进入统一记录，观点回溯仍独立管理。

讲解重点：咨询记录解决“专家说了什么”，验收解决“成果是否合格”，评价解决“本次服务质量如何”，观点回溯解决“长期看判断是否准确”。

### 14.5 演示五：运营规则统一维护

1. 打开 `/expertTalentOperations`。
2. 展示标签分类、年龄和聘期规则。
3. 展示匹配权重合计必须为100%。
4. 打开费用标准，说明来源于方案第14页。
5. 打开表单与模板，预览调用申请表、声明和咨询记录。
6. 展示通知开关和操作日志。

讲解重点：运营管理用于统一承载规则，避免各业务页面分别硬编码；当前为演示配置中心。

## 15. 验收标准

### 15.1 入库流程

- 能从推荐名单选择人员并发起邀请。
- 短信内容明确引导专家到小程序查看。
- 专家可以同意/拒绝邀请并完成六步资料。
- PC资料核对能看到专家提交的全部内容。
- 不满足条件时不能发起领导审批。
- 审批详情体现总监和分管领导节点，不展示抄送。
- 分管领导通过后进入待签发聘书，而不是直接入库。
- E签宝聘书签署成功后才正式入库。

### 15.2 调用流程

- 正式在聘专家可以从档案发起调用，其他状态按钮禁用并提示原因。
- 调用申请字段完整，支持PDF预览和打印。
- 任务列表支持组合筛选和重置。
- 推荐匹配表在正确状态可通过单选框或整行选择。
- 锁定排期后生成邀约和 E签宝声明签署信息。
- 声明未签署时咨询记录不可编辑。
- 声明签署成功后咨询记录解锁。
- 咨询记录支持草稿、正式提交、PDF预览和打印。
- 验收通过进入待评价，退回补充保留原因和期限。
- 待评价时只有评价表单可编辑。
- 提交评价后任务变为已完成，并同步到评价与回溯页面。

### 15.3 隔离和演示边界

- `/gzthome` 的现有逻辑和页面不发生变化。
- 所有未接真实服务的能力必须显示演示提示。
- 不使用真实个人证件、手机号、项目材料或签署文件作为演示数据。

## 18. 演示口径提醒
