# `/expertTalentList` · 在库专家功能介绍

更新日期：2026-09-14

本文说明专家管理页「在库专家」Tab 的需求定位和现有功能。该 Tab 管理已经完成正式入库的专家长期档案，回答「有哪些专家、能力如何、当前能否调用」，并办理续聘、解聘。尚未入库的人在同页「入库办理」Tab，两套数据分开管理。

当前为本地前端演示：数据保存在浏览器，续聘审批走原工作台待办，调用跳转到调用管理页。短信、审批流、小程序均未接真实服务。

---

## 1. 入口与页面位置

路径：`/expertTalentList`。侧栏菜单为「专家管理」。页面不再单独做大标题或身份头图，顶栏就是一级 Tab：

- **在库专家**（打开本地址时的默认 Tab）
- **入库办理（N）**

地址始终是 `/expertTalentList`。切换 Tab 不改 pathname、search 或 hash。刷新后回到「在库专家」。

本 Tab 顶栏右侧：

| 按钮 | 作用 |
|---|---|
| 页面说明 | 介绍专家管理用途、角色和流转规则 |
| 导出 | 演示占位，当前未接真实导出 |
| 邀请专家 | 切到「入库办理」，并打开内部「初始推荐名单」，不自动弹出邀请框 |

从档案抽屉点「发起调用」会离开本页，跳到 `/expertTalentTasks` 并带上当前专家。

---

## 2. 需求定位

在库专家是「已经聘任、可以长期管理」的档案库，不是入库申请单。

| | 在库专家 | 入库办理 |
|---|---|---|
| 管理对象 | 已正式聘用的专家档案 | 推荐名单与入库申请 |
| 回答的问题 | 库里有谁、能不能调用、聘期是否到期 | 这个人办到哪一步了 |
| 何时出现 | 入库办理发送聘书后自动新增；页面也预置演示档案 | 发出合作邀请后生成申请 |
| 主要动作 | 检索、查看档案、续聘、解聘、发起调用 | 邀请、核对、审批、发聘书 |

产品规则（与演示实现一致的部分）：

1. 只有发送聘书后才生成可调用档案。专家在小程序只需确认合作邀请，首次入库不需要再签聘书。
2. 首次及续聘聘期固定 3 年。
3. 普通专家年龄上限 65 周岁，高层次专家 70 周岁。
4. 聘期结束或年龄上限前 90 天触发预警。
5. 续聘须分管领导审批；通过后登记续聘聘书，聘期生效。
6. 达到年龄上限预警窗口内，可主动解聘。
7. 仅正式聘用、聘期未结束、且不是「限制调用 / 已解聘」的专家可以发起调用。

「忙碌」表示当前有在办任务，「限制调用」表示合规限制、不可新增调用。演示数据按状态预置，列表不会根据真实任务自动改状态。

---

## 3. 主流程（在库之后）

```text
入库办理发送聘书
  → 在库专家新增一条档案，状态一般为「可用」
  → 日常：检索、查看档案、在可调用时发起调用
  → 聘期结束前 90 天：预警，可发起续聘
        → 续聘审批中（分管领导在原工作台办理）
              ├─ 退回：恢复「待续聘」，可改后重提
              └─ 通过：待签发续聘聘书
                    → 登记续聘聘书（固定 3 年，不得超过年龄上限）
                    → 状态回到「可用」，当前聘期更新
  → 年龄上限前 90 天：预警，可主动解聘
        → 状态变为「已解聘」，只读保留档案，不可再调用
```

## 4. 状态筛选

列表上方是一行状态 pill。点一次按该状态筛选，再点一次取消。左侧「全部专家」不按状态过滤。

| 状态 | 含义 | 本页主要操作 |
|---|---|---|
| 全部专家 | 不按状态筛选 | 查看全部在库档案 |
| 可用 | 可发起调用 | 查看档案、发起调用；聘期临近时可续聘 |
| 忙碌 | 当前有在办任务 | 查看档案；聘期有效且未限制调用时仍可发起调用 |
| 待续聘 | 聘期临近，需办理续聘 | 查看档案、发起续聘；预警窗口内也可解聘 |
| 续聘审批中 | 分管领导审批续聘中 | 查看档案和流程编号；到工作台审批 |
| 待签发续聘聘书 | 审批已通过 | 登记续聘聘书 |
| 限制调用 | 合规限制，不可新增调用 | 查看档案；不可发起调用；聘期临近仍可续聘 |
| 已解聘 | 已退出专家库 | 只读查看历史；不可调用、续聘、解聘 |

当前演示数据约 22 人，上述状态均有样例。

## 5. 列表

筛选区与表格在同一张卡片里。

### 5.1 检索

| 条件 | 规则 |
|---|---|
| 关键词 | 匹配姓名、单位、专家编号、技术标签 |
| 主领域 | 下拉，选项来自当前在库专家的主领域 |
| 状态 | 上方 pill，与下拉互不影响；点「重置」清空关键词、领域和状态 |

有状态筛选时，表格上方出现「已按某某筛选」，可清除。右上角显示当前结果人数。

### 5.2 列

| 列 | 内容 |
|---|---|
| 专家 | 头像字、姓名、专家编号、职务。点姓名也可打开档案 |
| 单位 | 所在单位 |
| 领域与标签 | 主领域；最多展示 2 个技术标签 |
| 等级 | 如资深专家、高级专家 |
| 状态 | 彩色标签 |
| 项目/评分 | 历史项目数 / 综合评分 |
| 可服务时间 | 如「本周可约」 |
| 操作 | 查看档案 |

分页每页 8 条，底部显示「共 N 位专家」。

点行内姓名或「查看档案」打开同一份「专家档案」抽屉。

## 6. 专家档案抽屉

标题「专家档案」。右上角「发起调用」按能否调用启用或禁用，悬停可见原因。

头部展示：姓名字头像、姓名、当前状态、单位与职务、技术标签、综合评分。

内部四个页签。

### 6.1 基本档案

| 字段 | 说明 |
|---|---|
| 专家编号 | 如 `EX20260018`；入库发送聘书时按年份和序号生成 |
| 专家等级 | 档案字段，演示预置或入库时写入 |
| 专家类别 | 如产业研究、技术研发 |
| 主领域 | 如智能网联、新能源动力 |
| 联系电话 | 演示掩码 `138****5621` |
| 出生日期 | 用于年龄上限计算 |
| 服务意愿 | 即可服务时间 |
| 历史项目 | 项目个数 |

下方「专业画像」为演示文案，说明擅长方向。当前不是按履历自动生成。

### 6.2 聘期管理

顶部预警条：

| 情况 | 提示 |
|---|---|
| 已解聘 | 「专家已解聘」 |
| 距年龄上限 ≤ 90 天 | 红色：距 65/70 周岁还有 N 天 |
| 距聘期结束 ≤ 90 天 | 黄色：距当前聘期结束还有 N 天 |
| 其他 | 绿色：当前聘期正常 |

说明文案：系统在聘期结束或年龄上限前 90 天触发预警；普通专家上限 65 周岁，高层次专家 70 周岁。`highLevel` 为真时按高层次计算。

展示项：出生日期、当前年龄与上限日期、当前聘期起止、续聘审批流程编号（无则「—」）。

操作按钮按条件出现，不同时堆出全部动作：

| 按钮 | 出现条件 |
|---|---|
| 发起续聘 | 状态为「待续聘」；或聘期 90 天预警且状态为「可用 / 忙碌 / 限制调用」 |
| 登记续聘聘书 | 状态为「待签发续聘聘书」 |
| 主动解聘 | 年龄 90 天预警，且状态为「可用 / 忙碌 / 限制调用 / 待续聘」 |

「历史聘书」表：聘书编号、签订日、聘期、附件。首次入库发送的聘书和续聘聘书都记在这里。

### 6.3 调用记录

演示表，列：项目、角色、状态、评分。与调用管理页的真实任务列表尚未打通，条数用档案上的 `projects` 展示在页签名上。

### 6.4 合规与轨迹

时间线，记录入库发聘书、续聘发起、审批意见、续聘聘书签发、主动解聘等。格式：`时间 · 操作人 · 说明`。

## 7. 续聘

续聘不在入库办理列表里办，对象是已在库专家。审批与首次入库共用 `/djghome?task=expertEnrollmentApproval`。

### 7.1 发起续聘

弹窗字段：

| 字段 | 规则 |
|---|---|
| 续聘理由 | 必填 |
| 新聘期起始日 | 必填；须晚于当前聘期结束日。打开时默认从当前聘期结束日次日开始 |
| 新聘期结束日 | 只读，起始日加 3 年再减 1 天 |

提交前校验：结束日必须等于自动 3 年结果；结束日不得超过年龄上限日。二次确认后：

1. 状态变为「续聘审批中」
2. 生成演示流程编号 `RENEW-FLOW-…`
3. 写入续聘申请（理由、拟聘期、发起时间）
4. 轨迹记一笔

提示：提交后请在原工作台审批。

### 7.2 分管领导审批

待办来源包括「领导审批中」的入库申请，以及「续聘审批中」的在库专家。领导填写意见后通过或退回。

- 通过：状态变为「待签发续聘聘书」
- 退回：状态恢复「待续聘」，可改理由和聘期后重新发起

本 Tab 没有跳转审批待办的按钮，需从工作台进入。

### 7.3 登记续聘聘书

弹窗字段：聘书编号、签订日、起始日、结束日（自动 3 年）、聘书附件。结束日仍不得超过年龄上限。二次确认后：

1. 写入历史聘书
2. 当前聘期更新为新起止日
3. 状态回到「可用」，风险记为「正常」
4. 清除续聘申请和流程编号
5. 轨迹记签发信息

续聘聘书在 PC 登记即生效，演示不走专家小程序电子签。

---

## 8. 主动解聘

仅在年龄上限 90 天预警窗口内，且专家尚未解聘、不在续聘审批/待签发续聘聘书时出现。

弹窗必填：解聘原因、生效日期、情况说明。二次确认后：

1. 状态变为「已解聘」
2. 写入解聘记录
3. 轨迹记原因、生效日和说明

已解聘档案留在列表，可查看，不可发起调用、续聘或再次解聘。

---

## 9. 发起调用

档案抽屉右上角「发起调用」。

允许点击的条件（须同时满足）：

1. 历史聘书中至少有一条已登记签订日（或状态为「已签署」）
2. 当前聘期尚未结束
3. 状态不是「限制调用」或「已解聘」

否则按钮禁用，原因分别为「尚未正式聘用或聘期已结束」或「当前状态为某某，不可发起调用」。

通过后关闭抽屉，跳转：

`/expertTalentTasks?create=1&expertId=专家编号`

调用管理页打开《专家调用申请表》并预选该专家。匹配阶段也只允许选正式聘用、聘期有效、未限制调用、未解聘的人。

「忙碌」只要聘期有效且未限制调用，仍允许发起调用（演示不因忙碌自动禁调用）。

---

## 10. 档案从哪里来

1. **演示预置**：`data.js` 中的在库专家，覆盖全部状态，便于直接讲续聘、解聘和限制调用。
2. **入库办理发送聘书**：若该申请还没有对应档案，则在列表头部插入一条：
   - 编号：`EX` + 年份 + 序号
   - 姓名、单位、职务、类别、领域、标签来自履历/申请
   - 是否高层次：专家类别文案是否含「高层次」
   - 状态「可用」，综合评分演示 90，历史项目 0
   - 当前聘期与聘书记录来自本次发送的聘书
   - `sourceInvitationId` 指向原入库申请，避免重复生成

推荐名单和入库申请不会出现在本 Tab。未发聘书的人只能在「入库办理」里查。

## 11. 与其他页面的关系

| 页面 | 关系 |
|---|---|
| 入库办理 | 发聘书后写入本 Tab；「邀请专家」从本 Tab 切过去 |
| 调用管理 | 从档案发起调用；匹配时读取本 Tab 档案是否可调用 |
| 专家库看板 | 展示在库人数、可用人数等演示指标，并可跳进专家管理 |
| 运营管理 | 配置年龄上限、聘期年数、预警天数等规则口径；本 Tab 计算目前按代码写死 65/70 周岁、3 年、90 天 |
| 分管领导待办 | 办理续聘审批（以及首次入库审批） |

关闭抽屉或切到「入库办理」时，本 Tab 的关键词、领域、状态筛选和选中档案会保留。刷新后一级 Tab 回到「在库专家」，筛选重置。

## 12. 演示边界

- 数据只写当前浏览器本地存储，换设备或清缓存会丢失。
- 「导出」没有真实文件下载。
- 「忙碌 / 限制调用 / 待续聘」等列表状态以预置数据为主；抽屉预警按今天和聘期/生日计算，两者可能不完全同步。
- 续聘审批是工作台本地办理，没有真实账号鉴权和流程引擎。
- 续聘聘书只登记编号和文件名，没有 E 签宝。
- 调用记录页签是示意数据，不读取调用管理任务。
- 联系电话在档案里掩码展示。
- 专业画像是固定演示文案。
