# `/expertTalentList` · 入库办理功能介绍

更新日期：2026-09-14

本文说明专家管理页「入库办理」Tab 的现有功能。该 Tab 承接原「入库管理」页面，办理推荐名单、合作邀请、资料核对、分管领导审批和发送聘书入库。在库档案仍在同页的「在库专家」Tab，两套数据分开管理。发送聘书后即生成可调用专家档案，专家在小程序只需确认合作邀请，不需要签署聘书。

当前为本地前端演示：数据保存在浏览器，短信、审批流、小程序和 E 签宝均未接真实服务。

---

## 1. 入口与页面位置

路径：`/expertTalentList`。侧栏菜单为「专家管理」。页面不再单独做大标题或身份头图，顶栏就是一级 Tab：

- **在库专家**
- **入库办理（N）**，N 为当前入库申请条数

打开该地址时默认「在库专家」。进入「入库办理」的方式：

| 入口 | 结果 |
|---|---|
| 点击一级 Tab「入库办理」 | 打开入库工作区，地址仍为 `/expertTalentList` |
| 「在库专家」顶栏「邀请专家」 | 切到「入库办理」，并打开内部「初始推荐名单」，不自动弹出邀请框 |
| 看板「处理待办」「查看全部」「入库审核」 | 打开本页并定位到「入库办理」 |
| 旧地址 `/expertTalentApplications` | 重定向到本页并打开「入库办理」 |
| 分管领导审批待办中的「前往业务页面」 | 同上 |

刷新页面后一级 Tab 回到「在库专家」，因为地址不携带 Tab 信息。

「入库办理」顶栏右侧只保留：

- **页面说明**：简要介绍本页用途和流转规则
- **发起合作邀请**：打开「发送专家合作邀请」弹窗，从仍处于「待邀请」的推荐名单中选择人员

本 Tab **没有**「前往分管领导审批待办」按钮。分管领导仍在 `/djghome?task=expertEnrollmentApproval` 办理审批，需从工作台待办进入。

嵌入专家管理页时，不再显示黄色演示提示条。

---

## 2. 业务定位与主流程

入库办理管理的是「申请过程」，不是已经在库的专家档案。推荐名单、入库申请、在库专家仍是三套数据。

```text
需求部门推荐候选人员
  → 股权运营部维护「初始推荐名单」
  → 生成并发送《专家合作邀请函》，短信只通知专家到小程序查看
  → 专家在小程序点击确认
  → 发起邀约的人填写专家履历资料（可在专家确认前先保存）
  → 「待确认」提交后进入「待资料核对」
  → 履历自动带出《专家入库申请表》
  → 系统展示完整性、准入、关联合规三重校验（默认已确认，不可改）
  → 完成资料与申请核对
  → 发起分管领导线上审批
  → 审批通过后进入「待签发聘书」
  → 配置固定 3 年聘期并向专家发送聘书
  → 正式入库，生成可调用档案
```

需要区分的三个动作：

| 动作 | 含义 | 是否进入领导审批 |
|---|---|---|
| 发送合作邀请 | 询问专家是否愿意加入 | 否 |
| 专家在小程序确认邀请 | 表达合作意愿 | 尚未审批 |
| 发起分管领导审批 | 把核对完成的申请提交工作台 | 是 |

同意邀请不等于正式入库。发送聘书后即正式入库。履历由发起邀约的人维护，不能退回专家补充。

人员来源只分「内部 / 外部 / 参股企业」。不设置「7 类 / 5 类」、固定人数配额、名单批次或 CSV 导入。

## 3. 内部三个子 Tab

「入库办理」工作区内部仍保留三个子 Tab，不把推荐名单和申请列表合成一张表。**状态筛选各自挂在对应子 Tab 下面**，不再放在子 Tab 上方通栏。

### 3.1 初始推荐名单

维护尚未或准备发送合作邀请的候选人员。打开本子 Tab 后，列表上方提供状态筛选：

| 筛选 | 含义 |
|---|---|
| 全部名单 | 不按状态筛选，展示全部候选人员 |
| 待邀请 | 尚未发出合作邀请，可选中后转邀请 |
| 已转邀请 | 已发出合作邀请，复选框禁用，名单行仍保留 |

再点一次同一状态则取消筛选。条数随当前名单实时统计。

字段包括：人员来源、姓名、性别、单位、手机号、推荐部门、推荐人、关联项目、拟服务领域、推荐理由、状态。人员来源为「内部 / 外部 / 参股企业」。

功能：

| 功能 | 说明 |
|---|---|
| 搜索 | 按姓名、单位、来源、项目或领域过滤 |
| 新增候选人 | 弹窗录入上述字段。必填为姓名、性别、手机号；单位和拟服务领域非必填。保存后状态为「待邀请」 |
| 多选并转邀请 | 仅「待邀请」人员可选。点「选中人员转邀请」打开合作邀请弹窗并预填人选 |
| 状态 | 「待邀请」可继续发邀请；发出后变为「已转邀请」 |

从「在库专家」点「邀请专家」会打开本子 Tab，方便先找人或新增，再点顶栏「发起合作邀请」。

### 3.2 入库办理列表

展示已生成的入库申请（合作邀请发出后的办理单）。打开本子 Tab 后，列表上方提供阶段筛选：

| 阶段 | 含义 | 本页主要操作 |
|---|---|---|
| 全部办理中 | 不按阶段筛选 | 查看全部申请 |
| 待确认 | 等待专家在小程序确认合作邀请 | 办理详情中保存或提交资料 |
| 待资料核对 | 需核对履历与申请表 | 填写/修改履历和申请表，完成资料与申请核对 |
| 核对完成 | 核对已通过 | 填写发起说明（选填），发起分管领导审批 |
| 领导审批中 | 分管领导线上审批中 | 查看审批详情；到工作台办理 |
| 审批退回 | 审批未通过 | 修改后重新核对 |
| 待签发聘书 | 审批已通过 | 配置 3 年聘期并发送聘书 |
| 已正式入库 | 聘书已发送 | 查看聘书和聘期 |

再点一次同一阶段则取消筛选。有筛选时显示「已按某某阶段筛选」，可清除。

列包括：专家（姓名、单位/职务）、邀请函编号、拟服务领域、关联项目、推荐部门、当前阶段、最近更新。

操作：

- **办理详情**：打开右侧抽屉，查看资料并按阶段办理。
- **审批详情**：仅「领导审批中」显示，查看流程编号、申请事项和审批节点。

### 3.3 短信通知记录

发送合作邀请时自动写入一条模拟短信记录。列包括：接收人、手机号、短信内容、记录时间、状态。

短信文案示例：通知专家进入微信小程序「个人中心—入库邀请」，查看《专家合作邀请函》并确认。页面明确提示：短信只负责提醒，不替代正式合作邀请函；状态为「模拟记录·未真实发送」。尚未发过邀请时显示空态。

本子 Tab 没有阶段筛选。

## 4. 发送专家合作邀请

顶栏「发起合作邀请」，或在推荐名单中「选中人员转邀请」，都会打开同一弹窗。

填写项：

| 字段 | 规则 |
|---|---|
| 从初始推荐名单选择人员 | 可多选，仅「待邀请」人员可选，支持搜索 |
| 合作邀请函编号 | 必填，默认按当年序号生成；多人时自动加 `-1`、`-2` 后缀 |
| 邀请函模板 | 「专家合作邀请函（标准版）」或「专项咨询合作邀请函」 |
| 合作邀请说明 | 非必填 |

弹窗没有邀请有效期。取消按钮文案为「取消」。

确认后：

1. 为每人生成一条入库申请，阶段为「待确认」。
2. 对应推荐名单状态改为「已转邀请」。
3. 写入短信通知记录。
4. 自动切到内部「入库办理」列表。

这一步不进入领导审批。

## 5. 办理详情抽屉

标题为「专家入库办理详情」。这是入库办理的核心工作面，按区块组织。

### 5.1 底部按钮

底部按钮只在「待确认」出现，其余阶段底部无按钮（右上角关闭仍可用）。

| 当前阶段 | 抽屉底部 |
|---|---|
| 待确认 | **保存**、**提交** |
| 待资料核对 | 无 |
| 核对完成 | 无 |
| 领导审批中 | 无 |
| 审批退回 | 无 |
| 待签发聘书 | 无 |
| 已正式入库 | 无 |

- **保存**：写入履历草稿和由履历带出的申请表，阶段仍为「待确认」，抽屉不关。
- **提交**：同样写入资料，阶段变为「待资料核对」，然后关闭抽屉。

后续阶段的办理按钮在正文「阶段办理」中，不放在抽屉底部。

### 5.2 基本信息

展示专家姓名与单位、当前阶段、合作邀请函编号/模板、关联项目、推荐部门，以及四个办理条件：

- 专家是否已同意邀请
- 履历是否已填写
- 入库申请表是否已完成
- 三重校验是否已确认（默认已确认，不可改）

### 5.3 专家履历资料

履历由发起邀约的人维护，不是专家在小程序填写。可「填写履历资料」或「修改履历资料」。进入「领导审批中」「待签发聘书」「已正式入库」后锁定。

必填：姓名、性别、出生日期、证件号码、联系电话。证件类型默认「身份证」，可选护照或其他。

其余字段包括：邮箱、工作单位、职务/职称、最高学历与教育起止、工作经历、从业年限、专家类别、主领域/细分方向、技术关键词、代表项目、可承担角色、证书、成果/获奖、常驻城市、服务形式与时间、出差意愿、证明附件，以及诚信、保密、利益关联和个人信息授权声明。

尚未填写时提示：由发起邀约的人维护履历资料。专家在小程序只需确认合作邀请。

完成核对前须已保存履历，且专家已确认邀请。申请表可由发起人提前填写，提交「待确认」时会按履历自动带出。

### 5.4 需求部门《专家入库申请表》

申请表按纸质入库申请表排版，身份与履历段落从专家履历带出，不再单独填「入库必要性」等七项评价字段。

身份区：

- 专家姓名、性别、出生日期
- 证件号码、工作单位、职级/职称
- 联系电话、电子邮箱、最高毕业院校及专业

正文区：

- 教育背景
- 工作经历
- 资质与证书
- 专长领域与研究方向

身份区必填项填齐即可视为申请表完整。进入「领导审批中」及之后的锁定阶段后，申请表只读。

### 5.5 三重校验

系统展示三项校验结果，默认已确认且不可修改，不需要人工勾选复核：

| 校验项 | 演示结果 | 说明 |
|---|---|---|
| 资料完整性 | 通过 | 必填资料、履历及证明材料齐全 |
| 准入条件 | 通过 | 从业年限、专业经历满足演示准入规则 |
| 关联与合规 | 通过 | 未发现明确冲突 |

没有「我已人工复核该项结果及相关材料」勾选项。

### 5.6 阶段办理

按当前阶段给出不同操作。资料核对意见、发起审批说明均为选填。没有退回专家补充资料的权限，资料由内部填写。

**待确认**

- 等待专家在小程序点击确认合作邀请。
- 发起人可先填写履历；底部用保存/提交处理资料。
- 提交后进入「待资料核对」。

**待资料核对 / 审批退回**

- **完成资料与申请核对**：须同时满足：专家已确认邀请、履历必填项已填写、申请表完整。完成后进入「核对完成」。

**核对完成**

- **发起分管领导审批**：发起说明选填。提交后生成演示流程编号，阶段变为「领导审批中」。页面提示：将在原工作台生成分管领导审批待办；审批通过后还需签发聘书。

**领导审批中**

- 提示到原工作台审批待办办理。
- 可打开「审批详情」：流程编号、专家、申请事项、当前状态、发起时间，以及申请人已发起、运营部核对通过、总监审批通过、分管领导待审批的节点示意。

**待签发聘书**

- **发送聘书**：打开「发送专家聘书」弹窗。
  - 聘期固定 3 年，选择开始日期后自动计算结束日期。
  - 普通专家年龄上限 65 周岁，类别含「高层次」为 70 周岁；聘期结束日不得晚于该上限日。
  - 必填：聘书编号、聘期开始、聘书文件（演示登记文件名）。
  - 确认后直接进入「已正式入库」，并在「在库专家」中新增一条可调用档案（状态「可用」，带聘期和来源申请编号）。若该申请已生成过档案则不再重复新增。不需要专家电子签章。

**已正式入库**

- 只读展示聘书编号和聘期，不再提供核对或发聘书操作。

### 5.7 办理轨迹

时间线记录邀请发送、专家确认、履历填写、申请表填写、保存/提交、核对、发起审批、领导意见和发送聘书等操作人、时间和说明。

## 6. 分管领导审批（关联功能）

入库办理页负责准备资料并发起审批，不在本页填写通过/退回结论，也不再提供跳转到审批待办的页头按钮。

分管领导在 `/djghome?task=expertEnrollmentApproval` 查看待办，打开详情后：

- 查看专家资料、申请内容和历史轨迹。
- 填写审批意见。
- 选择通过或退回。

通过后申请进入「待签发聘书」。退回后进入「审批退回」，意见写入办理轨迹，由发起人修改后重新核对并再次提交。无待办时展示空状态，不编造虚假任务。

续聘审批也在同一待办入口，但办理对象是已在库专家，不属于本 Tab 的入库申请列表。

---

## 7. 与「在库专家」的关系

| | 入库办理 | 在库专家 |
|---|---|---|
| 管理对象 | 推荐名单与入库申请 | 已正式聘用的专家档案 |
| 何时出现档案 | 发送聘书后 | 发送聘书后自动新增 |
| 能否调用 | 否 | 状态为「可用」等且未解聘时可发起调用 |

「邀请专家」只是把用户带到推荐名单，真正发函仍用「发起合作邀请」。关闭抽屉或在两个一级 Tab 之间切换时，各自的筛选和内部子 Tab 会保留；刷新后一级 Tab 回到「在库专家」。

## 8. 演示边界

以下能力目前只在本机演示，不能当作已接通的生产服务：

- 数据只写当前浏览器本地存储，换设备或清缓存会丢失。
- 短信未调用真实短信服务商。
- 专家确认邀请依赖小程序演示，两端数据不自动同步。履历由 PC 端发起人填写，不经过专家签署聘书。
- 分管领导审批是工作台本地办理，没有真实账号鉴权和流程引擎。
- 聘书文件只登记名称，没有真实签章文件流。
- 页面预置了各阶段示例申请，便于演示后半段；这些记录不是小程序提交后实时同步得到的。
